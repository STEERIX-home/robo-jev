# 다섯 가지 설계 변경 검토

검토일: 2026-09-18. 대상: `README`, 01~06 문서와 제시된 수정 이유. 이 문서는 검토 결과이며, 기존 설계 문서의 변경 사항을 자동으로 확정하는 문서는 아니다.

## 1. 판정

다섯 변경의 방향은 대체로 타당하다. 후보마다 상태를 다시 처리하는 비용을 줄이고, 지연을 실제로 측정해 backbone을 고르며, 하네스의 기여와 모델의 기여를 구분하도록 바꾼 점은 유지할 만하다. 다만 **학습 라벨과 확률의 의미를 먼저 수정해야 한다.** 현재 규칙대로 데이터를 늘리면 잘못된 행동을 정답으로 만들거나, 학습으로 식별되지 않은 확률 차이를 실행 판단의 근거로 사용할 수 있다.

사용자가 정한 목표는 그대로 유지해야 한다. 모델은 하네스가 제공한 새로운 분야·질문·타입·후보의 의미를 해석하는 판단 모델이다. 결합 행동 후보와 고정 질문 prefix는 첫 로봇 하네스의 구성이지, 모델 전체의 고정 출력 스키마가 아니다. 로봇 데이터 비중을 높이는 것과 범용 의미 일반화 목표를 없애는 것은 다른 결정이다.

| 변경 | 검토 결과 | 남은 조건 |
| --- | --- | --- |
| 결정 위치 pointer readout | 유지할 만함 | `Q×K → Q` 분기 감소는 타당. 전체 비용의 K 독립성이나 R의 품질 상한은 보장되지 않음 |
| 지연 예산에서 backbone 선정 | 유지할 만함 | FLOPs 산식은 예비 추정. 실제 readout·상태 공유·캐시 구현으로 최종 검증 필요 |
| 결합 행동 후보의 단일 choice | 첫 통제 실험에 적합 | 조합 문제를 후보 목록으로 옮긴 것. 후보 포함률과 지시·목표를 반영한 라벨 필요 |
| 질문 선행 prefix L1 | 비교 실험으로 적합 | L1-a의 질문 간섭을 범용 계약에 섞지 않고, 실제 새 토큰·warm 지연을 측정 |
| 규칙 기준군·안정성·로봇 데이터 확대 | 유지할 만함 | 의미 조건을 포함한 기준군, 완전한 행동 동일성 규칙, 라벨 수정 후 데이터 확대 |

## 2. 실행 전에 수정할 사항

### R1 · P1 — 행동의 실행 성공을 지시에 맞는 행동의 정답으로 바꾸고 있다

위치: [02 §7](02-task-and-learning-problem.md), [04 §4, 허용 집합 규칙](04-data-generation-plan.md), [06 Task 3](06-execution-roadmap.md).

04는 grasp 후 lift의 성공을 사건 예로 든 뒤, 주 결정의 정답을 “최고 성공 횟수와 1회 이내이고 절반 이상 성공”으로 만든다. 02는 rollout 상태에서 기존 허용 집합을 이 규칙으로 다시 산출하도록 연결한다. 지시·목적지·우선순위·금지 조건에 부합하는지 확인하는 단계가 이 연결에 명시되어 있지 않다.

예를 들어 지시가 “빨간 물체를 집어라”이고 빨간 물체의 파지가 6/8, 파란 물체의 파지가 8/8 성공하면, 현 규칙은 파란 물체만 정답으로 만든다. 기하적으로 유효한 후보들을 제공해 의미 판단을 학습하려는 목적과 충돌한다. observe·hold·replan과 grasp의 서로 다른 사건 성공률도 그대로 비교할 수 없다.

수정 요구:

- 지시와 제약에 따른 의미 적합성 라벨을 보존한다. rollout 결과가 이를 덮어쓰지 않게 한다.
- 주 결정의 비교 기준을 동일한 목표·시간 범위·후속 정책 아래의 작업 성과로 정의하거나, 의미 적합성으로 제한한 후보들 사이에서 정의된 실행 성과를 비교한다.
- 관측·보류 같은 행동은 그 행동에 맞는 정보 획득 또는 후속 작업 성과로 평가한다. 비교 가능한 근거가 없으면 별도 근거 라벨이나 loss mask를 사용한다.
- 의미 적합성, 물리적 사건 결과, 최종 choice 라벨과 그 생성 규칙을 별도 필드로 보존한다. 정답 라벨을 이용한 제한을 추론 시 후보 생성기로 누출시키지 않는다.
- “1회 이내”는 8회 반복에서 12.5%p, 16회에서 6.25%p로 기준이 달라진다. censoring 때문에 유효 반복 수가 다르면 성공 횟수 자체도 비교할 수 없다. 목표 성과 차이와 표본 불확실성을 반영하는 규칙으로 바꾼다.

동일한 물리 성공률을 유지하고 지시·목적지만 바꾼 대조 사례에서 주 결정 정답이 적절하게 바뀌는지 먼저 검사해야 한다. 언어에 따른 스킬 적합성과 실행 가능성을 나누는 것은 [SayCan의 공식 설명](https://say-can.github.io/)에서도 구분하는 요소다.

### R2 · P1 — 허용 집합 손실만으로 후보별 보정 확률을 식별할 수 없다

위치: [03 §4](03-model-and-training-design.md), [02 §4 결정 유지 규칙](02-task-and-learning-problem.md).

03은 허용 집합 손실이 집합 내부의 상대 확률을 가르치지 않는다고 정확히 명시했다. 그러나 주 결정에는 이 손실을 적용하면서, 실행 단계에서는 후보 확률 차이 `δ=0.15`를 사용한다. 따라서 이 차이를 무엇으로 해석할지 계약이 필요하다.

허용 집합이 `{A, B}`일 때 다음 두 출력의 집합 손실은 같다.

| 출력 `(A, B, C)` | `-log(p(A)+p(B))` | `p(A)-p(B)` |
| --- | --- | --- |
| `(0.989, 0.010, 0.001)` | 약 0.0010005 | 0.979 |
| `(0.4995, 0.4995, 0.001)` | 약 0.0010005 | 0 |

동일한 정답성과 손실인데 전환 판단은 달라진다. temperature 조정만으로 집합 내부의 누락된 선호 정답을 알아낼 수는 없다. 별도 평가로 선택 정답 여부의 보정을 확인하는 일과, 각 후보의 상대 선호 확률이 검증되었다는 주장은 구분해야 한다.

수정 요구:

- choice 분포의 의미를 명시한다. 허용 집합 학습만 쓰는 주 결정에서는 확률 차이를 우선 개발 데이터에서 조정하는 점수 차이로 취급한다.
- 상대 선호 분포를 목표로 한다면 그 분포의 생성 과정과 검증 근거를 정의하고 적절한 분포 손실을 쓴다. 임의로 성공률을 softmax했다고 보정된 선호가 되지는 않는다.
- 물리적 성공 확률은 기존의 사건별 Bernoulli 계약을 유지한다. 서로 동시에 성공할 수 있는 후보들의 성공 확률을 합이 1인 choice로 바꾸지 않는다.
- K 변화, 후보 추가·삭제, 동등 후보 복제에 따른 점수 차이와 전환 결정을 평가한다. 같은 `δ`가 모든 후보 집합에서 같은 의미를 갖는다고 가정하지 않는다.

이 문제는 집합 손실을 버려야 한다는 뜻이 아니다. 정답 집합 학습, 후보 간 선호, 사건 확률, 실행용 전환 점수를 구분해야 한다는 뜻이다.

### R3 · P2 — 결정 유지에 쓰는 행동 동일성 키가 불완전하다

위치: [02 §3~§4](02-task-and-learning-problem.md), [06 Task 3](06-execution-roadmap.md).

결합 후보는 기능·대상·접근·목적지·프로파일을 포함하지만, 유지 규칙의 의미 키에는 목적지가 빠져 있다. 같은 물체를 왼쪽에 놓는 행동과 오른쪽에 놓는 행동이 같은 키가 될 수 있다. 목표가 바뀌거나 행동이 완료됐을 때 commitment를 해제하는 조건도 명확하지 않다.

수정 요구:

- 목적지, 목표 버전, 행동 의미를 바꾸는 파라미터를 동일성 정의에 포함한다. 연속 좌표의 작은 추정 변화는 명시한 허용 오차로 구분한다.
- 실행 완료·취소·목표 변경·후보 무효화의 commitment 전이와 카운터 초기화를 정의한다.
- `m=2`는 동일한 도전자 후보가 연속 조건을 만족해야 하는지 명시한다. 도전자나 목표가 바뀌면 카운터를 재설정한다.
- 전환율을 낮추는 효과와 함께 목표 변경 후 반응 지연, 완료된 행동의 반복 실행, 목적지 변경의 누락을 검사한다.

### R4 · P2 — pointer의 비용 감소를 K와 무관한 비용으로 설명하고 있다

위치: [README 변경 기록](README.md), [01 §6](01-research-concept-and-goals.md), [03 §3](03-model-and-training-design.md).

pointer는 후보마다 backbone 분기를 만드는 비용을 없앤다. 하지만 후보 설명을 인코딩하는 비용은 남고, 후보 벡터의 projection·점수 계산·softmax·분포 반환도 K에 따라 증가한다. full-attention 구간에서는 늘어난 토큰과 기존 토큰의 attention 비용도 생긴다. 따라서 “후보가 늘어도 추가 비용은 설명 토큰뿐”과 “선택지 수와 무관한 지연”은 정확한 비용 계약이 아니다.

설명은 “후보별 backbone 재실행과 순차 출력 생성을 없애고, 질문당 한 경로에서 후보 분포를 읽는다”로 바꾸는 것이 맞다. 총 토큰 길이와 후보 수를 각각 통제한 측정으로 실용적인 K 증가 비용을 보고해야 한다.

후보별 분기 R도 수학적인 품질 상한이 아니다. 추가 연산을 사용하는 비교군이며, 어느 쪽이 더 좋은지는 학습과 평가 결과에 달려 있다.

### R5 · P2 — backbone 선정 게이트가 실제 실행 구조보다 앞서 확정된다

위치: [06 Task 2b와 Task 4](06-execution-roadmap.md), [05 G0a](05-experiment-and-cloud-plan.md).

Task 2b는 L0/L1 지연과 무학습 라벨 점수로 backbone을 확정하지만, 실제 pointer·hybrid 분기·prefix 구현은 Task 4에 있다. native forward 또는 B1으로 측정한 시간은 유용한 예비 측정이지만, 최종 P1의 kernel·cache 복제·메모리 이동·readout 비용을 포함하지 않는다. D0 64건에서 우연 이상이라는 기준도 최종 의미 일반화의 품질 게이트로는 약하다.

게이트를 두 단계로 나눠야 한다. 먼저 native 실행으로 메모리와 지연이 명백히 맞지 않는 후보를 거른다. 이후 최소한의 실제 실행 경로와 짧은 readout 적응을 구현하고, 별도 D1 dev 품질과 연속 틱 p95/p99로 최종 선정한다. 최종 구조 검증 전에는 대규모 학습으로 확대하지 않는 원칙을 유지한다. 예비 측정만으로 최종 속도나 학습 후 품질을 보장하지 않는다.

### R6 · P2 — 비교 실험과 예산의 미반영 사항은 본 실험 전에 해결해야 한다

위치: [README 마지막 변경 기록](README.md), [03 §6](03-model-and-training-design.md), [05 §6](05-experiment-and-cloud-plan.md).

P0/P1은 같은 가중치의 공유 유무 비교다. 05의 “두 경로×3 seeds”가 이 둘을 별도 학습한다는 뜻이라면 공유 계산의 효과를 검증하는 데 불필요한 학습을 반복하게 된다. 반대로 다른 두 학습 구조를 뜻한다면 무엇인지 확정되지 않았다. B1에도 같은 prefix 공유 기회를 줘야 pointer 자체의 이점을 평가할 수 있다.

최소 비교표를 다음처럼 확정할 것을 권고한다.

| 학습·readout 방식 | 공유 없음 | 공유 있음 |
| --- | --- | --- |
| 후보 라벨 토큰 점수 B1 | B1-U | B1-S |
| pointer | P0 | P1 |

각 행은 같은 checkpoint로 두 실행 조건을 비교하고, 행 사이의 학습 범위·데이터·예산은 맞춘다. 예를 들어 두 학습 방식에 3 seeds면 6개 checkpoint이고, 실행 조건마다 따로 12개를 학습하는 것은 아니다. B0는 생성 방식의 실용 기준군, R/L1은 별도 추가 실험으로 배정한다. 학습과 추론 평가 시간, 프로파일링 시간을 분리해 비용표에 매핑해야 한다.

## 3. 수정 이유의 공개 근거를 해석할 때 정정할 점

TypeSafe가 공개한 제품 설명은 70~500ms 응답과 Doom의 초당 10회 질의를 제시한다. 이것은 우리 backbone·하드웨어의 실측이 아니다. 질문 독립성과 조건부 질문의 병렬 사용은 공식 primitives 설명과 부합한다. [TypeSafe 소개](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [Primitives](https://docs.typesafe.ai/primitives).

Hume의 57.5ms, 218ms, 610ms는 재계산해 확인했다. 다만 측정값은 **`x-envoy-upstream-service-time` 헤더의 서버 시간**이다. GPU kernel 시간이나 클라이언트 end-to-end 지연이 아니며, queueing·실행 경계와 서버 부하는 통제되지 않았다. [분석 글의 Methods](https://archerhume.com/posts/jevs-architecture-unmasked/?v=3), [공개 지연 원자료](https://archerhume.com/research/jev/latency-rerun.json).

| 공개 원자료 조건, 각 8회 | 서버 시간 중앙값 | 클라이언트 wall time 중앙값 |
| --- | --- | --- |
| 질문 1개, 입력 360 tokens | 57.5ms | 약 247.45ms |
| 질문 1개, 입력 29,835 tokens | 218ms | 약 413.25ms |
| 질문 1,500개, 입력 26,524 tokens | 610ms | 약 1,176.55ms |

두 상태 길이 사이의 기울기는 약 5.45µs/token이며, 이를 보간한 3K 입력의 약 72ms 역시 해당 서버 시간의 추정이다. 이를 1×H100 모델 시간 추정과 바로 나누어 정확한 배속 차이로 해석하면 측정 범주가 섞인다.

후보 수 지연 통제 실험은 주로 2~200개를 다뤘다. 255개 응답의 지원·토큰 계산 관측과 K 독립성의 실측 주장을 구분해야 한다. 관측된 지연이 거의 일정했다는 결과가 무제한 후보 수의 계산량 불변을 뜻하지 않는다. [후보 수 지연 원자료](https://archerhume.com/research/jev/option-count-latency.json).

MoE 약 10B active·8×H100은 관측과 양립하는 Hume의 추정이며 공개된 Jev 구성은 아니다. pointer와 slot head 중 무엇인지도 확정되지 않았다. RLCD의 정확한 공개 재현이라고 부를 수 없으며, proper scoring loss를 선택했다고 자동으로 분포가 보정되지는 않는다. [Hume의 구조 가설과 한계](https://archerhume.com/posts/jevs-architecture-unmasked/?v=3).

따라서 다음 표현은 약하게 고쳐야 한다.

- **“2~5Hz에서만 사용 가능, 10Hz 이상 불가”**: 현재 자원·토큰 예산에서 검증할 목표/가설이다. 모델 크기·하드웨어·입력 길이 변화까지 포함한 구조적 불가능 판정은 아니다. 현재 입력·출력 계약으로 영상 기반 연속 운동 정책을 재현하지 않는다는 판단은 타당하다.
- **“범용 zero-shot 재현 불가, OOD는 base 수준”**: 적은 데이터로 Jev 수준을 보장할 수 없다는 뜻으로 제한한다. 후속 학습이 새로운 의미의 판단을 개선하거나 악화하는지는 holdout으로 검증할 사안이다.
- **성공 가능성 85%·80%·20%·70% 등의 수치**: 근거 있는 확률 예측으로 취급하지 않는다. 자원 집행은 실측 게이트로 결정한다.
- **“결합 후보로 조합 폭발 해결”**: 조합 일관성은 개선하지만 곱으로 늘어나는 조합은 후보 수로 이동한다. 현재 문서의 K 상한·후보 포함률·선행 호출 비용 기록을 유지한다.

## 4. 확인된 반영과 실행 순서

현재 7개 문서에는 다섯 변경이 반영되어 있다. hybrid의 recurrent/conv 상태 격리, L1-a/L1-b 구분, 동적 결합 후보 때문에 prefix 절감 폭이 제한된다는 설명, 규칙 기준군, 안정성 지표도 확인했다. 원본 DOCX의 G0에는 단순 규칙·최소 ID로 해결되는지 확인하는 항목이 있어 규칙 기준군 복원 취지도 맞다.

수치 산술은 일치한다. GPU 합계 $8,753.92와 예비 20% 포함 $10,504.70, pilot 57,600회와 확장 1,152,000회 rollout, 5초 horizon 기준 80시간과 1,600시간의 모의 시간이 맞다. 이는 단가·처리량의 신규 검증이나 실행시간 보장이 아니다. 모델·시뮬레이터·GPU 실행은 이번 문서 검토에서 수행하지 않았다.

권고 순서는 다음과 같다.

1. R1/R2의 라벨과 확률 계약을 확정하고, 지시 변경·여러 허용 후보의 작은 대조 데이터로 확인한다.
2. R3의 행동 동일성·완료·목표 변경 전이를 정의한다. 규칙 기준군에도 입력에 이미 주어진 목표·제약을 동등하게 제공한다.
3. R4의 비용 주장을 수정하고, R5의 예비/최종 선정 게이트와 R6의 실험표를 비용·일정에 연결한다.
4. 100개 rollout과 실제 실행 경로의 profile 결과를 얻은 뒤 57,600개 데이터 제작과 본 학습으로 확대한다.

로봇 60% 비중은 첫 실험값으로 둘 수 있다. 이 비중이 범용 판단에 가장 좋다는 근거는 아직 없으므로, 로봇 성과와 새 분야·새 질문 의미의 holdout 성과를 함께 유지해야 한다.
