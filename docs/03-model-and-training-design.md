# 모델 구조와 학습 설계

작성일: 2026-09-18 · 상태: 구현 전 연구 설계. 아래 수치는 첫 실험의 시작값이며 측정 결과가 아니다. 같은 날 근본 검토를 반영해 backbone의 지연 예산 선정, 결정 위치 pointer readout, 질문 선행 배치 변형을 추가했고, 이어 [스트리밍 계약](08-streaming-io-and-data-contract.md)에 따라 로봇 기본 배치를 L1-a 스트림으로 명시하고 결정 분기·상태 전달·윈도우·truncated BPTT·부분 라벨 손실을 추가했다.

이 문서는 [연구 컨셉](01-research-concept-and-goals.md)과 [하네스의 역할](02-task-and-learning-problem.md)을 실제로 학습할 계산 구조에 연결한다. **질문·후보 생성은 하네스와 데이터 제작 파이프라인의 책임이며, 모델의 학습 목표는 주어진 판단 문제의 답이다.**

## 1. 첫 모델의 출발점

첫 입력은 하네스가 정리한 텍스트·구조화 상태다. 물체 정보, 좌표, 정밀도, 시각, 불확실성, 목표, 실행 후보의 설명을 직렬화한다. 이미지·점군에서 물체를 인식하는 능력까지 한 번에 학습하지 않는다. 실로봇의 주 앞단은 3D 카메라 → 3D 재구성 → 고정 추출 모듈이며, 같은 스키마를 채우는 한 앞단을 바꿔도 모델을 다시 학습하지 않는다. 원시 이미지·기하 soft token 입력은 별도의 확장 실험으로 다룬다([스트리밍 계약](08-streaming-io-and-data-contract.md) 1절).

| 구분 | 제안 | 선택 이유와 조건 |
| --- | --- | --- |
| 첫 후보이자 품질 기준 | `Qwen/Qwen3.8-27B` | 공개 가중치의 dense 모델이다. 아래 지연 예산을 실측으로 통과하면 같은 backbone에서 데이터 규모와 반복 실험을 확대한다. |
| 지연 예산에 따른 비교 후보 | active 파라미터가 더 작은 공개 dense·MoE, full-attention 모델 | 로봇 판단 주기의 지연 예산이 허용하는 규모 안에서 고른다. 후보와 선정 기준은 아래 절에 둔다. |
| 소형 계산 검사 | 임의 가중치의 소형 attention/DeltaNet fixture | mask·상태 분기·gradient의 수학적 정합성만 검사하며 성능 비교에 사용하지 않는다. |
| 모델 확정 시점 | 후보별 지연·무학습 판단 품질 측정과 첫 500개 상태의 분기·메모리 파일럿 이후 | 새 질문의 판단 품질과 학습 가능한 분기를 확인한다. 작은 모델의 속도를 구조 개선으로 보고하지 않는다. |

공식 저장소는 Qwen3.8-27B의 2026-08-14 공개를 기록한다. 공식 모델 카드는 공개 가중치·Apache-2.0·시각 입력 지원과 27B 언어 모델을 설명한다. 최신 계열을 검토하지 않았던 기존 Qwen3-14B→32B 선정안을 폐기하고 Qwen3.8-27B부터 검증한다. Qwen3 계열은 아래 선정 절차의 full-attention 비교 후보로만 남긴다. [공식 공개 기록](https://github.com/QwenLM/Qwen3.8/blob/main/README.md), [공식 모델 카드](https://huggingface.co/Qwen/Qwen3.8-27B)

모델 다운로드 전에 revision SHA·라이선스·파일 해시를 manifest에 고정한다. 첫 학습은 text backbone 전체와 판단 readout을 대상으로 하고, vision encoder는 고정하며 이미지 입력 실험은 분리한다. 시각 기능이 있다는 이유로 이번 연구에서 지각 학습까지 완료했다고 주장하지 않는다. 초대형 Qwen3.8-2.4T-A95B도 공개되어 있으나, 현재 단일 노드 학습 예산의 기본 후보로 넣지 않는다. [초대형 모델 카드](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B)

### 지연 예산에서 역산하는 backbone 선정

로봇의 판단 주기가 모델 규모의 상한을 정한다. prefill만 수행하는 직접 readout의 지연은 새로 계산하는 토큰 수와 active 파라미터에 거의 비례한다.

```text
모델 지연 ≈ 2 × N_active × 틱당 새 토큰 수 / 실효 FLOPs/s + 고정 비용
N_active 상한 ≈ 실효 FLOPs/s × 모델 시간 예산 / (2 × 틱당 새 토큰 수)
```

아래는 단일 H100의 BF16 prefill 실효 처리량을 4×10¹⁴ FLOPs/s(피크의 약 30~50%)로 가정한 계산 예시다. 측정값이 아니며 PCIe 모델은 더 낮을 수 있다. attention의 길이 제곱 항과 고정 비용은 제외했다.

| 모델 시간 예산 | 틱당 새 토큰 1,000 | 2,000 | 3,000 |
| --- | --- | --- | --- |
| 150ms (5Hz 주기 안) | 약 30B | 약 15B | 약 10B |
| 80ms (10Hz 주기 안) | 약 16B | 약 8B | 약 5B |

이 가정에서 27B dense는 틱당 새 토큰을 약 1.1K 이하로 유지해야 5Hz에, 약 550 이하로 유지해야 10Hz에 들어온다. 로봇 스트림(L1-a)의 틱당 새 토큰은 설계 시 400~600으로 추정했으나, 옛 서식(h0.3/ts0.3)의 실측은 최초 틱 1,764~3,469, 후속 틱 최대 3,712였다. **계약 v0.3(서식 축약·변화분 틱, 2026-09-19 실측, 08 §3.4)에서는 10물체·K=12 장면의 틱당 p50 392, p95 662, 첫 틱 943(+prefix 451), 100틱 구간 43.4K이고 재생성한 batch-0(40편) 실측은 p50 443·p95 608·100틱 49K**다 — 예산(500/800/1,200/60K) 안이다. 또한 배포·실행 장비는 H100이 아니라 DGX Spark/Jetson급 엣지(≈273GB/s, H100의 1/4~1/8 연산)이므로 이 표는 참고이고 **지연 판정은 배포급 장비에서 대표 입력(현재 서식 하한·상한, K=32, 지시 변경 틱, warm history 30틱)으로 실측**한다. BF16이 주 비교 조건이고 FP8은 kernel 지원·양자화 대상·품질 차이를 명시한 별도 조건이다. 본선은 아래 Spark 실측으로 **2B(주)·4B(5 Hz 대비)**로 좁혔고(2026-09-19), G0b의 `stream` 경로 실측(2026-09-20, 아래 표)으로 **Qwen3.5-2B + `fused` 지렛대(틱 몸통과 10개 결정 분기를 한 forward로)**를 10 Hz backbone으로 확정했다 — 40편 batch-0 재실측 upper p95 62.7 ms·batch-0 60.2 ms, 100 ms 초과 2/1,348틱(0.15 %; 기본 서빙 구성 `all`은 52.5 / 52.0 ms·초과 0); 4B는 `fused`/`all`로 5 Hz 예산(150 ms)만 든다. 무학습·readout-only·LoRA 품질은 같은 후보에 대해 G0b가 쟀다(06 Task 2b 2단계 결과). 틱당 토큰이 더 크면 active 약 10B 이하의 모델이나 여러 GPU에 나눈 서빙이 필요하다. 공개 분석이 관측한 Jev의 지연(360 tokens 57.5ms, 약 30K tokens 218ms)은 **서버 응답 헤더 시간**이며 GPU 시간도 클라이언트 전체 지연도 아니다(같은 원자료의 클라이언트 wall time은 서버 시간의 2~3.5배). 그 기울기 약 5µs/token은 서버 처리의 상한으로만 해석하며, 같은 가정의 27B dense·단일 GPU 계산값(약 135µs/token)과 범주가 달라 정확한 배속 차이로 쓰지 않는다. 후보 수 실험도 2~200개 범위이고 입력 길이 효과와 분리되지 않았다. 이 수치는 목표 설정의 참고이고 우리 모델의 성능으로 사용하지 않는다. 읽는 법(리뷰 1 I6). 문자 그대로의 판정은 native의 **자라는 캐시**(윈도우 없이 15.7K→31K)에서 잰 p95와 초과율이다: 2B는 세 프로파일 모두 `fails_10hz`(p95 97~103 ms > 80)이고 upper·지시 변경은 초과율 0.11·0.14 > 0.05라 **`deadline_fail`**이다 — 넘긴 틱은 983~997토큰의 소개·갱신 틱이다. 윈도우 크기 값은 `model_ms ~ cache_before`의 최소제곱 직선을 측정 범위(15.7K~31K)**보다 짧은** 12.8K~13.2K로 **외삽**한 것(R² 0.25~0.59)이라 첫 5틱 평균(70.7 / 73.8 ms, 캐시 ≈16K)을 옆에 둔다. 두 읽기가 모두 80 ms 안일 때 참인 기계 판독 `passes_10hz_window`(2B lower·upper 참, 4B 거짓)를 `fails_10hz` 옆에 두어 G0b의 `stream` 경로(정적 윈도우 KV)와 같은 잣대로 비교한다 — 판정은 그 경로의 실측이 한다. 4B는 5 Hz(150 ms) 사정권(외삽 144~149 ms)이다.

토큰 비례 항은 실효 ≈97 / 78 / 118 TFLOPS로 GB10 BF16 dense 상한과 같은 자릿수의 연산이고, 절편이 4B→9B에서 +42 ms 느는 것은 launch-bound보다 weight-read(≈273 GB/s에서 9.5 GB ≈ 35 ms)에 가깝다 — 어느 쪽인지는 G0b에서 profiler·CUDA graph로 귀속 측정한다. attention 항은 2B에서 캐시 1K 토큰당 ≈2.1 ms로 윈도우 틱(≈83 ms)의 ≈40%이며 FLOP 시간(≈4 ms)의 ≈8× — sdpa가 마스크를 물질화한 채 sm80용 memory-efficient 커널로 실행되기 때문이다. 따라서 위 H100 표의 9B 25 ms 같은 계산값은 배포 장비에서 성립하지 않으며, 지연 판정은 이 실측과 G0b의 `stream` 경로 실측으로 한다. cold(무상태 재계산)는 warm의 7~25×라 캐시·윈도우 경로가 전제다.

## 2. 요청과 출력 계약 v0

모든 질문에는 의미를 설명하는 문장과 판정 기준이 있어야 한다. `target`, `intent` 같은 ID만 보고 답을 추측하게 학습하지 않는다. ID는 입출력 연결용이며, 모델 입력에는 순서를 섞은 요청 내 별칭과 후보 설명을 사용한다.

| 타입 | 요청 내용 | 모델 출력 |
| --- | --- | --- |
| `choice` | 질문, 후보 ID·설명·참조 정보 | 각 후보의 확률, 선택된 후보 ID |
| `boolean` | 판정할 명제와 참·거짓의 기준 | `true`, `false` 분포와 `p_true` |
| `ordinal` | 질문, 순서가 있는 수준별 설명·수치 | 수준별 분포, 하네스가 제공한 수치에 대한 기댓값 |

`ordinal`의 수치는 하네스가 정의한다. 예컨대 수준 값이 `[0, 2, 5]`면 점수는 `sum(p_k * value_k)`다. 이것이 물리 단위의 연속 회귀 정확도를 보장하지는 않는다. 같은 타입으로 전혀 다른 분야의 질문을 받을 수 있으며, 분야별 전용 출력 head는 만들지 않는다.

하네스가 `정보 부족`, `해당 없음`, `관측 추가`를 의미 있는 후보로 제공하면 모델이 선택할 수 있다. 모델이 요청에 없던 후보를 만들지는 않는다. 빈 후보, 중복 ID, 해석할 수 없는 타입, 길이 초과는 입력 오류로 반환하고 조용히 잘라내지 않는다. 확률이 분산되어 있다는 사실과 정보가 부족하다는 의미적 판단도 구분한다.

초기 프로파일은 `Q=1~16`, 질문별 후보 `K=2~32`, 공통 상태 최대 2,048 tokens, 요청 전체 최대 8,192 tokens로 시작한다. `K`의 상한을 32로 둔 것은 [첫 로봇 하네스](02-task-and-learning-problem.md)의 주 결정 질문이 대상·접근·프로파일을 묶은 결합 행동 후보를 한 목록으로 받기 때문이다. 게이팅·진단 질문의 후보는 보통 2~8개다. 이 상한은 구현·메모리 검증용이며 모델의 의미 범위가 아니다. 상한들이 동시에 최대일 수는 없다. 전체 길이를 검사하며, 이후 `Q=32`, `K=64`, 전체 16K로의 확장을 별도 측정한다.

## 3. 직접 readout 계산 구조

첫 구현은 다음 두 단위로 구성한다. 각 단위의 텍스트는 추론 시작 전에 모두 알려져 있다.

```text
S: 공통 지침 + 분야 문맥 + 현재 상태
T_i: 질문 i + 타입 + 판정 기준 + 전체 후보 목록(후보 k의 끝에 경계 위치 c_ik) + 결정 위치 d_i

S ─┬─ T_1: [질문·기준][후보 1 … c_11][후보 2 … c_12] … [d_1] → 질문 1의 softmax
   └─ T_2: [질문·기준][후보 1 … c_21][후보 2 … c_22] … [d_2] → 질문 2의 softmax
```

결정 위치 `d_i`는 후보 목록 뒤에 있으므로 공통 상태와 해당 질문의 모든 후보를 본다. 결정 위치의 표지 토큰은 요청 안의 질문 순서에 의존하지 않는다: 상태 선행(L0) 배치에서는 모든 질문이 **같은 고정 표지 토큰**을 쓴다(질문의 정체는 `T_i` 문맥이 준다 — 그래야 질문 추가·삭제·재배열 불변이 구조로 성립한다). 스트림(L1-a) 배치에서는 분기가 1토큰이라 표지가 질문의 정체를 져야 하므로, 질문 세트 버전이 질문 id마다 표지를 고정해 정적 prefix에 선언하고 틱마다 묻는 부분집합·순서와 무관하게 유지한다. 후보 경계 `c_ik`의 hidden state는 그 후보의 의미를 담는다. 공통 pointer readout `z_ik = (U h_{d_i})ᵀ (V h_{c_ik}) / √r + b`로 후보별 logit을 얻고, 질문 하나의 logits만 모아 softmax한다. `U`, `V`, `b`는 모든 질문·타입이 공유한다. Boolean은 참·거짓 두 후보, ordinal은 수준별 후보로 같은 경로를 사용한다. 고정 `K`차원 분류기를 사용하지 않으므로 후보 수와 의미가 요청마다 바뀔 수 있다.

causal 구조에서 앞쪽 후보의 표현은 뒤쪽 후보를 직접 보지 못한다. 전체 목록의 정보는 결정 위치를 거쳐 모든 후보의 점수에 반영된다. 이 방식이 없애는 것은 **후보별 backbone 재실행과 순차 출력 생성**이며, 분기 수는 질문 수 `Q`다. 후보가 늘면 후보 설명 토큰의 인코딩, 후보 벡터 projection과 O(K) 점수 계산·softmax·분포 반환, 늘어난 토큰에 대한 full-attention 비용은 남는다. 비용이 `K`와 무관하다고 주장하지 않으며, 총 토큰 길이와 후보 수를 각각 통제한 측정으로 `K` 증가 비용을 보고한다. readout을 읽는 데 autoregressive 생성이나 JSON 파싱이 필요하지 않다.

### 추가 연산 비교군 R: 후보별 분기 readout

이전 설계안은 후보마다 `R_ik: "이 후보를 평가: <요청 내 별칭과 후보 설명>" + readout 위치` 분기를 두고 공통 scalar readout `z_ik = wᵀh_ik + b`를 적용했다. 모든 readout이 전체 목록을 본 뒤 자기 후보를 다시 읽으므로 후보 순서의 영향이 작을 수 있다. 그러나 분기 수가 `Q×K`이고 후보 설명을 두 번 읽는다. 대표 셀(`Q=8, K=4, S≈1024`, 질문 약 150 tokens, 후보 재제시 약 30 tokens 가정)의 처리 토큰은 아래와 같이 추정한다.

| readout | 복제 경로(P0) | 공유 경로(P1) | 분기 수 |
| --- | --- | --- | --- |
| 결정 위치 pointer (주 경로) | 약 9.4K | 약 2.3K | Q |
| 후보별 분기 (비교군 R) | 약 38K | 약 3.2K | Q×K |

후보별 분기는 주 경로로 사용하지 않고, D1 규모에서 추가 연산을 쓰는 비교군으로만 학습한다. 연산이 더 많다는 사실이 품질 상한을 보장하지는 않으며, 어느 쪽이 나은지는 학습·평가 결과로 정한다. pointer가 뚜렷이 뒤지면 결정 위치를 여러 개 두는 방법과 후보 경계 표현의 보강을 먼저 검토한다.

### 분기별 정보 접근과 위치 규칙

| 토큰 구간 | 볼 수 있는 내용 | 볼 수 없는 내용 |
| --- | --- | --- |
| `S` | `S` 안의 자신까지의 prefix | 모든 질문 |
| `T_i` (후보 경계·결정 위치 포함) | 전체 `S`, `T_i` 안의 자신까지 | 다른 질문 |
| 참고군의 `R_ik` | 전체 `S`, 전체 `T_i`, 자기 readout 구간의 자신까지 | 다른 질문, 다른 후보 readout 구간 |

각 질문의 논리적 position은 `len(S)`부터 시작한다. 참고군의 후보 readout은 `len(S)+len(T_i)`부터 시작한다. 묶음에서 앞에 놓인 다른 질문의 길이가 위치에 영향을 주지 않게 한다. Qwen3.8의 실제 position tensor는 공식 text-only 경로를 기준으로 모든 축의 일치 여부를 확인한다. 별개의 상태는 attention과 recurrent state 양쪽에서 격리한다.

첫 정답 구현 P0는 각 질문 i의 `S + T_i`를 별개의 causal sequence로 실행한다. 전체 후보 목록과 결정 위치가 T_i에 있으므로 후보 간 비교 정보를 유지한다. prefix를 질문 수만큼 반복 계산하는 비용이 있지만 attention·DeltaNet 모두에서 분기 간섭이 없는 기준을 얻는다. 이것만을 속도 비교의 유일한 기준으로 삼지 않고, 최적화된 생성·라벨 readout도 함께 비교한다.

P1은 층마다 S의 계산을 공유하고 S의 끝에서 질문별로 분기한다.

| 층 종류 | 공유 prefix의 상태 | 질문 분기에서 할 일 |
| --- | --- | --- |
| Full attention | prefix K/V와 hidden state | 자기 prefix와 자기 분기만 참조하도록 mask/cache를 구성 |
| Gated DeltaNet | recurrent state와 causal convolution의 history | S 끝의 상태에서 각 질문을 독립적으로 시작. 참고군은 T_i 끝의 상태에서 각 후보를 한 번 더 분기 |

Full-attention 층의 최적화 후보는 FlexAttention이다. DeltaNet 층은 초기 상태·최종 상태를 전달하는 별도 연산 경로가 필요하다. 공개 구현에도 convolution과 recurrent 상태가 따로 있으며, cache의 in-place 갱신 경로가 있으므로 그대로 공유하면 분기가 서로 오염될 수 있다. [FlexAttention 문서](https://docs.pytorch.org/docs/stable/nn.attention.flex_attention.html), [Transformers 공식 구현](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modeling_qwen3_5.py)

학습용 P1은 prefix 상태의 계산 그래프를 보존하고 분기에서 오는 gradient를 합해야 한다. 초기 recurrent state·convolution history에 대한 gradient 지원도 검사한다. 추론 cache가 존재한다는 사실만으로 이 학습 경로가 지원된다고 가정하지 않는다. in-place로 다른 분기의 상태를 덮어쓰거나 prefix에서 detach하지 않는다. 지원되지 않는 kernel은 미분 가능한 기준 연산으로 구현·검증한 뒤 최적화한다.

정합성 검사는 dropout을 끈 상태에서 P0/P1의 logits·loss·prefix와 backbone gradient를 대조한다. 작은 dense mask 검사는 full-attention 부분의 정답으로만 사용한다. DeltaNet의 분기 순서·초기 상태·conv history 검사는 별도로 수행한다. 상태 분기가 비용·품질 조건을 충족하지 못하면 문제와 대안 backbone의 비교 근거를 기록하고 모델 선정을 재검토한다.

질문 추가·삭제·재배열은 기존 질문 결과를 수치 오차 이상 바꾸지 않아야 한다. 후보의 순서 변경은 사전학습 표현 때문에 차이가 생길 수 있으므로 학습 증강과 평가로 다룬다. 후보 순서 불변성을 구조만으로 보장했다고 주장하지 않는다.

### 로봇 스트림 배치 (L1-a, 로봇 응용의 기본)

위 배치(L0, 상태 선행)는 한 상태에 많은 질문을 묻는 요청에 맞춘 것이다. 상태를 한 번만 읽고 질문이 그 뒤에서 분기한다. 로봇 폐루프는 구조가 반대다. 같은 질문 세트를 매 틱 다시 묻고 상태만 바뀐다. L0에서는 바뀐 상태 뒤에 놓인 질문 텍스트를 틱마다 다시 계산한다. 시점 사이에 재사용되는 것은 상태 앞의 정적 prefix뿐이다.

L1(질문 선행)은 틱 사이에 변하지 않는 내용을 모두 앞에 둔다. `|` 앞은 틱 사이에 캐시하고 뒤는 매 틱 계산한다. **로봇 응용의 기본 배치는 아래 L1-a**이며, 스트림 구조·상태 스키마·검사는 [스트리밍 계약](08-streaming-io-and-data-contract.md) 3절이 정본이다.

```text
L0: [정적 지침·능력] | [동적 상태] [질문 1..Q: 텍스트·후보·결정 위치]
L1: [정적 지침·능력] [질문 1..Q의 텍스트·정적 후보 설명] | [동적 상태] [동적 후보 값] [질문별 결정 위치]
```

| 변형 | 구성 | 대가와 적용 범위 |
| --- | --- | --- |
| **L1-a 격리 포기 (로봇 기본)** | 고정 질문 세트를 한 prefix에 순차로 두고, 틱마다 `[상태][실행 이력][동적 후보]`를 붙인 뒤 그 끝의 공통 상태에서 결정 위치 10개가 **일시적 1토큰 분기**로 갈라진다. 분기끼리는 attention mask로 차단하고 DeltaNet·conv 상태는 fork한다. 분기 상태는 버리고 **다음 틱은 분기 이전의 공통 상태에서 이어간다.** 채택된 답은 실행 이력 토큰으로만 다음 틱에 들어간다 | 일반 prefix cache와 상태 fork로 모든 backbone에서 구현된다. 상태 토큰이 질문 세트를 조건으로 하므로 질문 간 격리는 성립하지 않는다. 세트를 하네스 버전으로 고정하고, 세트 변경은 정합성이 아닌 품질로 평가한다. Full-attention 층은 정적 prefix + 최근 30틱을 보고, 학습과 추론이 같은 mask·position을 쓴다(공개 config의 전층 full attention을 바꾸는 사용자 정의) |
| L1-b 격리 유지 (별도 실험) | 질문 분기를 서로 격리해 캐시한다. 동적 상태는 질문을 보지 않고, 결정 위치만 자기 질문과 상태를 함께 참조 | Full-attention 층에서는 mask만으로 성립한다. DeltaNet 층은 두 분기의 recurrent state를 정확히 합칠 수 없어 질문 수만큼 상태를 다시 읽어야 하므로 hybrid 후보에서는 성립하지 않거나 이점이 작다. 질문과 상태의 융합이 결정 위치에 한정되어 품질이 떨어질 수 있다. full-attention 후보에서만 실험한다 |

절감 폭은 질문 텍스트 중 정적인 부분의 비율에 달려 있다. 결합 행동 후보처럼 틱마다 값이 바뀌는 후보는 어느 배치에서도 다시 계산한다. 첫 로봇 하네스의 10질문 세트에서 틱당 새 토큰은 [스트리밍 계약](08-streaming-io-and-data-contract.md) 3.4절의 추정으로 L1-a 약 400~600이고, 무상태 L0 요청은 여기에 질문 텍스트 약 400이 더해진다. 후보의 의미 설명은 정적 prefix에 두고 틱마다 바뀌는 기하 값만 동적 구간의 후보별 행으로 나누는 직렬화도 함께 비교한다.

L0와 L1은 정보 흐름이 다르므로 동일 가중치 비교가 아니다. 같은 초기 가중치·데이터·학습 예산으로 각각 학습해 판단 품질, 연속 틱 조건의 지연, 질문 세트 변경에 대한 민감도를 비교한다. 로봇 하네스처럼 질문 세트가 고정된 응용의 기본은 L1-a 스트림이고, 요청마다 질문이 달라지는 범용 경로의 기본 배치는 L0로 유지한다. 같은 readout이 두 배치를 처리하며, 로봇 비교군으로는 틱마다 이력을 텍스트로 넣는 무상태 L0 요청을 둔다.

스트림의 정합성 검사는 두 가지다. (1) 증분 계산(틱마다 새 토큰만)과 처음부터 계산의 결과가 같아야 한다. 윈도우 절단은 정의된 근사로 차이를 기록한다. (2) 질문 하나의 문구·후보를 바꿨을 때 다른 결정 분기와 다음 틱 공통 상태의 변화를 잰다. L1-a에서는 0이 아닐 수 있으므로 품질 지표로 보고하고, L0 경로에서는 수치 오차 안이어야 한다.

## 4. 학습 목표와 손실

기본 손실은 질문마다 계산한 뒤 상태 안에서 평균내고, 마지막으로 상태들 사이에서 평균낸다. 질문 수가 많은 상태가 무조건 더 큰 가중치를 갖지 않게 한다. 유효한 라벨이 없는 질문은 loss mask로 제외한다. 분야·타입의 표본 비중은 데이터 sampler가 관리한다.

```text
L_state = sum_i(mask_i * weight_i * L_i) / sum_i(mask_i * weight_i)
L_batch = mean(L_state over states with at least one valid label)
```

| 라벨 | 손실 | 해석상의 조건 |
| --- | --- | --- |
| 유일한 정답 후보 | Cross-entropy | 실제로 유일한 정답인 문제에만 사용 |
| 허용되는 답의 집합 A | `-log(sum_{k in A} p_k)` | 답들 사이의 상대 확률까지 정답이라고 가정하지 않음 |
| 허용 A + 미확인 U가 있는 집합 | `-log(sum_A p_k / (sum_A p_k + sum_I p_k))`, `I`는 부적합·열등 판정 후보 | rollout하지 않은 후보 `U`를 정규화에서 뺀 부분 라벨 손실. 스트림의 키프레임 틱에 사용 |
| 검증된 분포 | Soft-label cross-entropy | 출처·반복 수·불확실성을 함께 보존 |
| 실행 결과의 성공/실패 | Bernoulli NLL | 행동·후속 정책·시간 구간이 고정된 사건만 해당 |
| 순서 수준 | 수준 CE 또는 검증된 분포 CE | 첫 버전은 CE, 이후 누적분포 오차를 보조 손실로 비교 |

반복 시뮬레이션의 성공 `s`, 실패 `f`는 둘 다 저장한다. 질문별 평균 Bernoulli loss에 사용하며 반복 수가 많은 질문이 전체 학습을 독점하지 않게 가중치를 제한한다. 사람이나 teacher가 만든 선호 분포를 물리적 성공률 라벨로 사용하지 않는다.

결합 행동 후보를 묻는 주 결정 질문은 의미 적합성 → 실행 성과 → commitment 순의 규칙([스트리밍 계약](08-streaming-io-and-data-contract.md) 7절)으로 허용 집합을 산출해 집합 손실로 학습한다. 같은 rollout 횟수는 사건 확률 질문의 Bernoulli 라벨로도 쓴다. 선택 분포와 성공 확률의 두 라벨을 한 분포로 합치지 않는다. 집합 안의 상대 확률은 일반적으로 식별되지 않으며, commitment가 유일 정답을 만드는 틱에서만 정책 모방 라벨이 생긴다.

후보 순서 변경의 일관성 손실은 기본 CE 학습이 안정된 뒤 추가하는 ablation이다. 최초부터 많은 보조 손실을 섞어 개선 원인을 잃지 않는다. calibration은 학습·개발과 분리한 데이터에서만 수행하고, 적용 전·후 지표를 함께 보존한다.

## 5. 실제 학습 단계

| 단계 | 업데이트할 가중치 | 데이터·목적 | 산출물 |
| --- | --- | --- | --- |
| T0 | readout만 | 64개 확실한 상태에 과적합, mask·loss·저장 경로 진단 | 진단 checkpoint와 gradient 보고서 |
| T1 | 선정한 backbone(첫 후보 Qwen3.8-27B)의 text 가중치 전체 + readout | pilot의 train split으로 판단 학습, 새로운 의미 dev 확인. readout 참고군(R)과 배치 변형(L1)의 짧은 비교 포함 | 최초 학습 모델·곡선·오류 분석 |
| T2 | 같은 초기 가중치에서 두 학습 방식(B1, pointer)의 text backbone 전체 학습 | 데이터 곡선(로봇 에피소드 400/1,600/4,000 + 비로봇 2K/8K/20K), 각 checkpoint를 공유 없음/있음 두 조건으로 실행 | 데이터 곡선과 2×2 비교 결과 |
| T3 | 같은 초기 가중치에서 두 학습 방식의 반복 학습 | 최종 규모에서 2 방식 × 3 seeds = 6 checkpoint, 실행 조건은 checkpoint당 두 가지 | 본 실험 checkpoint와 독립 평가 |
| T4 | 선정한 학습 checkpoint | 새 오류 데이터와 이전 데이터의 혼합 후속 학습 | 개선판과 회귀 평가 |

T0는 완료 모델이 아니다. 메모리가 모자라면 LoRA·부분 학습을 별도 진단 조건으로 둘 수 있으나, backbone 전체 학습 계획을 조용히 대체하지 않는다. 구조 비교의 양쪽은 같은 업데이트 범위·초기 가중치·데이터 예산을 맞춘다.

첫 full finetuning 설정은 AdamW, backbone learning rate `1e-5`, readout `1e-4`, weight decay `0.01`, gradient clip `1.0`, warmup `5%`, 이후 cosine decay, BF16 연산·FP32 loss로 시작한다. 짧은 pilot에서 backbone LR `5e-6 / 1e-5 / 2e-5`만 먼저 비교한다. 이는 측정 전 시작값이며 최적값이 아니다.

목표 effective batch는 32개 상태다. 기본 8 GPU에서 rank당 1개 상태와 누적 4회로 시작한다. P0의 질문별 경로를 내부 microbatch로 나누더라도 상태별 loss 정규화를 유지한다. 참고군의 후보별 경로는 한 질문의 전체 logits를 모은 뒤 softmax한다. 최대 3 epoch 안에서 dev loss·분야별 정확도를 보고 checkpoint를 선택한다. test는 선택에 사용하지 않는다.

**스트림 데이터의 학습 시퀀스.** 에피소드를 순서대로 10초 구간(약 100틱; 구간 토큰은 실측 서식으로 176K~371K, 계약 v0.3 목표로 ≈50K — 설계 시의 55K 가정은 v0.3 이후에만 성립)으로 나누고, 같은 optimizer step 안에서 구간을 차례로 forward·backward하며 DeltaNet·conv 상태와 윈도우 KV를 detach해 다음 구간에 전달한다(truncated BPTT). 한 에피소드가 하나의 gradient accumulation 단위이고, 구간 경계에서 gradient는 끊긴다. 추론과 같은 가중치·같은 이력의 상태를 얻으므로 warm-up이 필요 없고 모든 틱에 loss를 준다. 결정 분기의 gradient는 공통 상태로 합쳐 전달한다. effective batch 32개 상태는 스트림에서는 에피소드 32개로 읽는다. 구간당 활성 메모리는 backbone 선정 기준에 넣는다.

한 번의 저장 단위에는 backbone, readout, tokenizer/revision, mask·직렬화 버전, optimizer/scheduler, RNG, sampler 위치, 데이터 manifest, 학습 설정을 포함한다. 배포용 가중치와 학습 재개용 checkpoint를 구분한다.

## 6. 비교 실험에서 분리할 질문

주 비교는 **출력 방식 × 공유 유무**의 2×2다. 행(출력 방식)은 각각 별도의 학습이고, 열(실행 조건)은 같은 checkpoint를 두 방식으로 실행하는 것이라 학습을 반복하지 않는다.

| 학습·readout 방식 | 공유 없음(질문별 독립 경로) | 공유 있음(공유 prefix·분기) | 학습 |
| --- | --- | --- | --- |
| 후보 라벨 토큰 점수 읽기 | **B1-U** | **B1-S** | 결정 위치의 LM logits에서 후보 별칭 토큰 점수를 읽도록 학습. 별칭은 단일 토큰으로 맞추고, 못 맞추는 조건은 별도 비용으로 기록 |
| 결정 위치 pointer readout | **P0** | **P1** | 이 문서의 주 경로 |

- 열 사이(B1-U↔B1-S, P0↔P1)는 **같은 가중치의 실행 방식 비교**다. logits·loss가 수치 오차 안에서 같아야 하고, 차이는 지연·메모리다.
- 행 사이(B1↔P)는 **같은 초기 가중치·데이터·학습 예산·업데이트 범위의 구조·학습 비교**다. B1에도 같은 공유 기회를 주어야 pointer 자체의 효과를 분리할 수 있다.
- 본 실험의 반복은 행에만 곱한다. 두 학습 방식 × 3 seeds = **6 checkpoint**이며, 실행 조건마다 따로 학습하지 않는다.

추가 비교군은 별도 배정한다.

| ID | 경로 | 목적 | 규모 |
| --- | --- | --- | --- |
| B0 | 같은 backbone의 최소 라벨 생성, 가능한 batch·prefix cache 사용 | 실제로 사용할 수 있는 생성 기반 기준군 | D1, 최종 규모 |
| R | 후보별 분기 readout, P0와 같은 데이터·학습 예산 | 추가 연산을 쓰는 비교군. 품질 상한을 보장하지 않음 | D1 |
| L1/L0 | 로봇 스트림 L1-a 대 무상태 L0 요청(틱마다 이력을 텍스트로), full-attention 후보에서는 L1-b 추가. 각각 학습 | 고정 질문 세트의 연속 틱 지연, 품질과 격리의 교환 | D1 |
| 규칙 기반 판단기 | 같은 하네스에서 모델 자리에 규칙 | 하네스만으로 해결되는 범위 | 폐루프 전체 |
| T (소형 scorer) | 사전학습 없이 처음부터 학습한 byte 수준 option-attention scorer(jevlike/cua-s1 계열, ≈1M 파라미터): 문맥 = 직렬화한 상태·질문, 후보 = 후보 줄. 같은 D1로 학습 | **데이터가 패턴 매칭으로 풀리는 정도**를 잰다. 이 기준군이 backbone에 근접한 분할·질문에서는 의미 판단을 주장하지 않는다 | D1(CPU, 하루 분량), Task 2c |

모든 평가에 **문맥 섞기 대조군**(배치 안에서 문맥을 한 칸 굴려 후보만 남긴 정확도)을 함께 보고한다 — 이 값이 높은 분할은 라벨·후보 단축 경로가 있다는 뜻이다. R과 L1/L0는 가중치가 달라지는 구조·학습 비교이며 D1 규모에서 먼저 수행하고, 확대는 2×2의 결과가 나온 뒤 남은 시간 풀에서 결정한다. 규칙 기반 판단기는 모델 구조의 비교군이 아니라 하네스만으로 해결되는 범위를 재는 기준이며 [학습 문제 정의](02-task-and-learning-problem.md)에 정의한다. B0의 label-only 결과와 전체 후보 분포가 필요한 제품 계약을 별도 보고한다. 학습 시간, 추론 평가 시간, 프로파일링 시간은 [GPU 계획](05-experiment-and-cloud-plan.md)의 비용표에 각각 매핑한다.

주요 축은 `N=1`, `Q={1,4,8,16}`, `K={2,4,8,16,32}`, 공통 상태 길이 `{512,2048}`다. 먼저 대표 셀 `Q=8,K=4,S≈1024`와 로봇 표준 묶음(주 결정 `K≈12` 1개 + 게이팅 4개)에서 품질과 성능을 확인하고 전체 축으로 확대한다. 16K, `Q=32`, `K=64`는 후속 확장이다.

캐시 없는 새 상태와 동일 상태의 재사용을 분리한다. 로봇 조건에는 **연속 틱 측정**을 추가한다. 같은 질문 세트를 유지한 채 매 틱(10Hz) 새 동적 상태를 넣고, 정적 prefix와 스트림 상태가 warm인 조건의 틱당 모델 시간과 관측→명령 적용 시간, 100ms deadline 초과율을 잰다. 공유 prefix로 줄어드는 입력 연산은 실제 mask kernel, 긴 질문, 메모리 이동, GPU 점유율에 따라 달라진다. 공통 상태 토큰 수가 줄었다는 계산만으로 2배 지연 개선을 확정하지 않는다.

## 7. 첫 모델 판정 기준

1. 64개 명확한 상태의 진단 학습에서 라벨 정합성과 loss 감소를 확인한다. 암기 성공을 일반화 성능으로 보고하지 않는다.
2. FP32 소형 hybrid 기준 구현에서 P0/P1의 logits·loss·gradient가 허용 오차 안에서 일치한다. BF16 허용 오차는 kernel별 반복 측정 후 benchmark 전에 고정한다. recurrent state와 conv history로부터 prefix까지 gradient가 전달되는지 포함한다.
3. 질문 추가·삭제·순서 변경에서 답의 의도치 않은 간섭이 없어야 한다. 후보 재배열 오차는 별도 품질 지표로 보고한다.
4. 의미 holdout에서 정확도·NLL·Brier와 정보 부족 사례를 평가한다. 낮은 entropy를 높은 실제 정답률로 자동 해석하지 않는다.
5. 동등한 기능·품질 조건의 지연을 비교한다. 본 로봇 시험의 비열등 기준은 [실험 환경 문서](05-experiment-and-cloud-plan.md)에 따라 파일럿 후 동결한다.
6. 10Hz 연속 틱 조건에서 실측한 모델 시간과 관측→명령 적용 시간이 예산 안에 있고 100ms deadline 초과율이 기준을 넘지 않는다. 미달이면 토큰 예산(변화분 틱), 서빙 구성, backbone의 순서로 조정하고 변경과 재측정 결과를 기록한다.
7. 관측 잡음 범위 안의 입력 변화에서 주 결정이 뒤집히는 비율을 보고한다. 폐루프의 결정 안정성 지표는 [학습 문제 정의](02-task-and-learning-problem.md)를 따른다.

**상태(2026-09-20, G0b 실측, `.superpowers/sdd/task-g0b-report.md`).** 2 — BF16 허용 오차를 실제 2B에서 5회 반복 측정해 상수로 고정(readout 위치 상대 L2 ≤ 0.04, 중앙값 ≤ 0.03, 전체 최대 ≤ 0.6; fp32 ≤ 0.03 — 공식 구현의 kernel 간 편차 안), recurrent·conv 상태의 prefix까지 gradient 전달 검사 통과. 3 — 결정 분기 배치가 서로의 상태(recurrent·conv·KV)와 다음 틱의 공통 상태를 바꾸지 않음(bit-identical)과 분기 부분집합의 logits가 전체 배치의 것과 BF16 상수 안에서 같음 검사 통과; 후보 재배열 지표(치환 답 변경률·선택 위치 분포)는 평가 표준 열이고 학습에 후보 순서 치환 증강이 든다 — 값은 아직 크다(T0 2B pilot dev 33 %). 4 — 봉인 holdout(ood_dev)의 정확도·NLL·Brier를 T0·LoRA·무학습에 대해 06 Task 2b 2단계 결과에 적었다(D1 dev는 5편이라 작다). 6 — **2B `fused` 경로 upper p95 65.0 / batch-0 57.3 ms, 100 ms 초과율 0 → 통과**(baseline은 upper에서 3.8 ms 미달); 4B는 5 Hz만. 1·5·7은 첫 학습 뒤.

다음 단계의 입력은 [데이터 생성 계획](04-data-generation-plan.md), 자원과 실행 조건은 [GPU·실험 계획](05-experiment-and-cloud-plan.md)을 따른다.
