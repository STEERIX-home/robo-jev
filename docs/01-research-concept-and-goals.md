# 병렬 판단 모델의 연구 컨셉과 목표

작성일: 2026-09-18

문서 상태: 연구 설계 초안. 같은 날 근본 검토를 반영해 지연 예산에 따른 backbone 선정, 결합 행동 후보의 주 결정, 규칙 기반 기준군과 결정 안정성, 로봇 스트리밍 배치를 추가했고, 이어 [스트리밍 계약](08-streaming-io-and-data-contract.md)에 따라 계층 정의·스트림 모드·격리 예외·연속 틱 지표를 반영했다. 모델의 역할은 하네스가 제공한 판단 문제에 답하는 것으로 정의한다. backbone·출력·학습의 초기안은 [모델 설계](03-model-and-training-design.md), 자원·평가 계획은 [실험 환경](05-experiment-and-cloud-plan.md)에 작성했으며 파일럿에서 검증한다.

## 1. 연구 컨셉

**공통 상태와 요청마다 달라지는 질문·타입·후보를 입력받아, 여러 판단의 선택·확률·점수를 병렬로 직접 출력하는 모델을 개발한다.** 충분한 사전학습 능력과 모델 규모를 유지하면서, 순차적인 응답 생성과 공통 상태의 반복 처리를 줄이는 계산 구조와 학습 방법을 연구한다.

하네스는 현재 분야와 상황에 필요한 정보를 모으고, 무엇을 물을지와 어떤 후보를 제공할지 구성한다. 모델은 각 질문의 의미와 후보를 이해해 판단 결과를 반환한다. 하네스는 그 결과를 정해진 규칙으로 조합하고 실행한다. 질문 생성, 후보 구성과 실행 절차 설계는 이 판단 모델의 출력 목표에 포함하지 않는다.

예를 들어 같은 상황에서 의도, 대상, 접근 방식, 이동 정도, 추가 관측 필요성, 실행 조건을 함께 물을 수 있다. 이런 항목은 요청에서 정하는 질문의 예시다. 모델 안에 영구적으로 고정할 질문 목록이나 행동 클래스가 아니다.

연구 목표는 새로운 질문과 후보 의미에도 반응하는 판단 능력이다. 로봇은 첫 개발·평가의 응용 분야로 두며, 모델 인터페이스와 질문별 출력 구조를 특정 로봇이나 여섯 가지 행동 이름에 묶지 않는다. 학습할 분야의 폭과 일반화 성능은 데이터 구성과 별도 평가로 확인한다.

## 2. 직접 개발할 연구 자산

개발 범위는 **모델 구조 설계 → 학습 데이터 생성 → 실제 모델 학습 → 체크포인트 산출 → 판단·폐루프 평가** 전체다.

- **모델:** 공통 상태 표현, 질문·후보 표현, 질문 분기의 병렬 계산, 후보의 공동 해석, 직접 확률·점수 출력과 상태 공유를 설계하고 구현한다.
- **데이터:** 다양한 상태·질문 묶음·타입·후보와 질문별 검증 라벨을 생성하는 파이프라인을 만든다. 로봇 실행 결과와 연결된 데이터도 구축한다.
- **학습:** 목적함수, 업데이트할 가중치, 학습 단계와 자원을 정하고 실제 학습을 수행한다. 설정·데이터·평가 결과에 연결된 체크포인트를 산출한다.
- **검증:** 질문별 판단 품질, 새로운 질문·후보에 대한 일반화, 한 상태의 질문 묶음 지연과 실제 작업 성과를 확인한다.

내부 표현과 가중치에 접근 가능한 사전학습 backbone을 출발점으로 사용한다. head-only 학습은 초기 출력 경로의 진단 조건으로 보존하며, backbone의 부분·전체 후속 학습을 포함한다. 모델 소형화·학생 모델 증류와 새로운 backbone의 처음부터의 사전학습은 현재 핵심 범위에 포함하지 않는다. 다만 backbone의 규모는 첫 응용의 판단 주기가 허용하는 지연 예산에서 역산해 고른다. 이는 학습한 모델을 작게 만드는 소형화와 다르며, 규모 고정의 원칙은 비교군 사이에 적용한다. 선정 절차와 후보는 [모델 설계](03-model-and-training-design.md)에 둔다.

## 3. 모델과 하네스의 책임

전체 흐름은 `목표·관측 → 하네스의 상태·질문·후보 구성 → 모델의 병렬 판단 → 하네스의 결과 조합 → 실행기 → 다음 관측`이다.

| 구성 요소 | 책임 | 비교 실험에서의 취급 |
| --- | --- | --- |
| 상위 작업 지능 | 목표·우선순위·제약·장기 전략 제공 | Astra/VLM 등을 사용할 수 있으며, 비교군에 같은 목표 명세를 제공한다. |
| 하네스의 입력 구성 | 분야별 문맥과 최신 상태 정리, 질문 분해, 타입·후보·평가 기준 구성 | 같은 버전·정보·규칙을 사용한다. 생성 비용과 후보 포함률을 기록한다. |
| 병렬 판단 모델 | 제공된 상태·질문·후보를 해석해 질문별 선택·확률·점수 반환 | 이번 연구의 핵심 개발·학습 대상이다. |
| 하네스의 결과 조합 | 사용할 답 선택, 조건·임계값·호환성 검사, 답을 실행 명령으로 매핑 | 조합 규칙과 판단에 대한 기여를 공개하고 고정한다. |
| 운동 실행기·컨트롤러(L1) | 명령의 좌표 변환, 말단 목표 추종(OSC 50Hz 갱신, 물리 500Hz), 명령 사이의 혼합 전이, 명령 수명(관측 deadline·발행 lease) 검사, 반사(힘 한계·근접·미끄러짐)와 정지 전이, 그리퍼 이벤트 변환 | 동일 구현과 제한을 사용한다. 명령 밖의 새 전략을 자동 선택하지 않는다. 계약은 [스트리밍 계약](08-streaming-io-and-data-contract.md) 6절 |
| Matrix Runtime | 관측 동기화, 요청·명령 버전, 유효성, 기록·연결·배포 | 하네스와 실행을 연결하며, 제어 제한은 모델과 독립적으로 유지한다. |

하네스는 단순 입출력 전달 이상으로 응용 로직을 갖는다. 어떤 정보를 묻고 어떻게 답을 사용할지가 시스템 성능에 기여하므로, 이 부분을 모델의 능력과 구분해 평가한다. 모델과 하네스를 합친 것이 실제 로봇의 의사결정 시스템이다.

로봇에서 이 모델의 자리는 상위 작업 지능(초 단위, CoT 추론)과 컨트롤러(50~500Hz) 사이의 **"의미에 대한 System 1"**이다. 실행 중에 전술이 바뀌는 상황에서 상위의 초 단위 지연을 100ms대로 줄이고, 물리 반사는 컨트롤러에 남긴다. 각 계층의 주기와 인터페이스는 [스트리밍 계약](08-streaming-io-and-data-contract.md) 2절에 둔다.

## 4. 모델의 입력과 출력

### 입력

하네스가 공통 상태 `S_t`와 질문 묶음 `Q_t`를 구성한다.

```text
Q_t = {q_1, ..., q_Q}
q_i = {instructions, type, criteria}
R_t = M_theta(S_t, Q_t)
a_t = H_compose(S_t, Q_t, R_t)
```

`S_t`에는 필요에 따라 목표·제약, 관측·시각, 최근 이력, 로봇 능력과 분야별 문맥이 들어간다. `instructions`는 판단할 내용, `type`은 답의 형식, `criteria`는 해당 질문의 선택지·수준·판정 기준이다. 질문 ID와 요청 버전은 하네스가 관리하며, 모델이 새 질문이나 후보를 생성하지 않는다.

### 출력

초기 핵심은 아래 판단 형태를 지원하는 것이다. API의 `choice`·`boolean`·`ordinal`과 첫 요청 크기는 [모델 설계](03-model-and-training-design.md)에 정의한다.

| 판단 형태 | 하네스가 제공할 내용 | 모델이 반환할 내용 |
| --- | --- | --- |
| 선택 | 질문과 요청별 후보·설명 | 후보 전체의 확률 분포와 선택 결과 |
| 이진 판단 | 명제와 참·거짓의 기준 | 명제가 참이라는 확률 |
| 수준 평가 | 질문과 순서가 있는 평가 기준 | 수준별 확률 분포와 그 기준에 따른 점수 |

필요한 confidence 통계는 반환된 분포에서 계산할 수 있다. 질문의 내용은 의도·대상·방법·정도·실행 가능성 등 요청에 따라 달라진다. 후보가 위치나 파라미터 프로파일을 참조하면 하네스는 선택된 참조를 실제 값으로 매핑한다. 모델이 처음부터 모든 자세·수치를 새로 만들어야 하는 구조를 기본 전제로 두지 않는다.

지원하는 판단 형태 안에서 새로운 의미의 질문·후보를 처리하는 능력과 새로운 기본 출력 타입을 지원하는 일은 구분한다. 연속 수치·벡터의 직접 예측은 기본 판단 경로를 검증한 뒤 검토할 확장이다. 이 경우에도 출력 명세와 제약은 하네스가 제공한다.

### 스트림 모드

1차 robojev는 **Physical State → typed Action** 모델이다. 입력은 하나의 공통 구조화 상태 스키마이고, 앞단(시뮬 참값, 3D 카메라 → 3D 재구성, 이미지 지각)은 그 스키마를 채우는 교체 가능한 모듈이다. 영상·기하 soft token은 슬롯만 예약한 확장이다. Jev의 공개 인터페이스도 구조화 상태 입력이다.

로봇처럼 같은 질문 세트를 매 틱 다시 묻고 상태만 바뀌는 응용에는 **스트림 모드**를 둔다. 에피소드 하나가 append-only 토큰 스트림이고, 지시·제약·질문 세트를 prefix에 둔 뒤 틱마다 상태·실제 실행 이력·동적 후보와 결정 위치를 붙인다. 운동 의도(경로·속도·힘)와 그리퍼 상태·정지도 같은 세 판단 형태의 질문으로 낸다. 스트림 모드에서는 질문 간 격리 대신 고정 질문 세트를 하네스 버전의 조건으로 삼는다. 계약은 [스트리밍 계약](08-streaming-io-and-data-contract.md)에 정의하며, 요청마다 질문이 바뀌는 단일 요청 모드와 같은 readout을 공유한다.

## 5. 병렬 판단의 사용 방식

공통 상태가 준비되어 있고 그 상태만으로 질문을 정의할 수 있다면 여러 질문을 한 요청에 담는다. 각각의 답은 다른 질문의 아직 생성되지 않은 답을 입력으로 요구하지 않는다. 모든 답을 반드시 실행에 사용할 필요도 없다.

제공된 브라우저 데모에서는 의도, 대상 요소, 사이트, 입력할 문자열 후보, 스크롤 정도, 명령 여부 등의 판단을 함께 구하고 실행 조건에 맞는 답을 사용한다. 로봇에서도 현재 상황의 대상·접근법·운동 후보·관측 필요성 등을 같은 방식으로 질문할 수 있다. 화면의 실행 지시는 사용 예시이며 로봇 모델의 고정 기능 목록이 아니다.

대상에 따라 접근법이 달라져도 무조건 순차 호출할 필요는 없다. 예를 들어 하네스가 “물체 A를 집는다면 어떤 접근 후보가 적절한가”와 “물체 B를 집는다면 어떤 접근 후보가 적절한가”를 미리 구성할 수 있으면 둘을 병렬로 묻고 선택된 대상의 답만 사용한다. 그러나 첫 로봇 하네스에서는 서로 결합된 선택을 유효한 조합의 **결합 행동 후보**로 묶어 한 질문으로 묻는 것을 기본으로 하고, 조건별 질문은 비교 구성으로 둔다([학습 문제 정의](02-task-and-learning-problem.md)). 어느 쪽이든 모델의 계약은 같다.

첫 답을 받아야 후보·관측 자체를 만들 수 있는 경우에는 다음 호출이 필요하다. 하네스가 이 의존성을 정하고, 질문 수가 늘어나는 비용과 순차 호출의 지연을 비교한다. 서로 다른 조건의 답을 무조건 조합하거나 질문별 확률을 독립적인 실행 성공 확률로 곱하지 않는다.

병렬화의 대상은 판단 계산이다. 실제 물리 동작의 동시 실행 여부는 하네스와 실행기의 자원·의존성 조건에 따라 별도로 정한다.

요청 구조도 응용마다 다르다. Jev의 공개 사용법은 한 상태에 많은 질문을 넣는 요청을 전제한다. 로봇 폐루프는 같은 질문 세트를 매 틱 다시 묻고 상태만 바뀐다. 이 차이는 무엇을 틱 사이에 재사용할지를 결정하므로, 상태 선행 배치와 질문 선행 배치를 별도 변형으로 비교한다([모델 설계](03-model-and-training-design.md)).

## 6. 모델 구조의 연구 원칙

- **직접 출력:** 입력 처리 뒤 readout에서 확률·점수를 얻는다. 결과를 토큰 단위로 생성하고 다시 읽는 반복을 줄인다. 계층 계산과 입력 길이에 따른 비용은 남는다.
- **공통 상태 공유:** 한 요청의 상태 처리를 재사용하고 질문·후보별 계산으로 분기한다. 캐시 없는 실행과의 정합성을 확인한다.
- **질문 내 후보 공동 해석:** 해당 질문의 전체 선택지를 함께 읽고, 목록 뒤의 결정 위치에서 후보별 점수를 읽는다. 후보별 backbone 재실행 없이 한 경로에서 후보 분포를 읽되, 후보 토큰의 인코딩과 점수 계산 비용은 남으므로 후보 수에 따른 비용을 측정해 보고한다. 후보 순서·ID에 의존하는 오류를 측정한다.
- **질문 간 격리:** 같은 상태에서 한 질문의 답이 다른 질문의 추가·삭제·순서에 의해 불필요하게 바뀌지 않도록 설계·검증한다. 답 간 의존성은 하네스가 명시한다. **예외:** 고정 질문 세트를 쓰는 스트림 모드(L1-a)는 상태 표현이 질문 세트를 조건으로 하므로 격리를 보장하지 않으며, 질문 세트 변경을 정합성이 아닌 품질로 평가한다.
- **새 상태 처리:** 변경되지 않은 정적 prefix만 시점 사이에 재사용한다. 상태가 바뀌면 의존 표현을 다시 계산하고 오래된 관측을 최신 정보로 취급하지 않는다. 질문 세트가 고정된 응용에서는 질문 텍스트를 정적 prefix에 두는 배치를 별도 변형으로 검증한다.
- **지연 예산과 규모:** 첫 응용의 판단 주기에서 틱당 새 토큰 수와 active 파라미터의 상한을 역산하고, 그 안에서 backbone을 고른다. 절대 지연은 `backbone × 계산 구조 × 서빙 하드웨어`의 조합으로 보고한다.
- **질문 의미에 따른 확률 해석:** 의도·선호의 선택 분포와 물리적 성공 확률을 구분한다. 성공 확률을 묻는 질문에는 실행 행동·후속 정책·평가 구간을 정의한 결과 라벨이 필요하다.

정확한 backbone, attention mask, readout 구조와 학습 레시피는 자체 연구 대상이다. Jev의 비공개 구조나 RLCD를 재현했다고 전제하지 않는다.

## 7. 연구 목표와 평가 단위

| 목표 | 확인할 내용 | 주요 근거 |
| --- | --- | --- |
| 질문·후보 의미의 일반화 | 요청마다 다른 분야별 문맥·질문·후보를 같은 체크포인트로 해석하는가 | 의미·질문 계열·후보 조합·응용 분야를 구분한 holdout |
| 병렬 판단 품질 | 여러 질문을 한꺼번에 처리해도 각각의 품질과 정합성을 유지하는가 | 질문별 오류·분포 평가, 단독 호출과 묶음 호출의 비교 |
| 판단 묶음 지연 개선 | 같은 상태의 필요한 판단을 더 빨리 준비하는가 | 상태별 p50·p95·p99, 준비 완료 시간과 마감 초과율 |
| 동적 환경 대응 | 상태가 매번 바뀌어도 새 질문 묶음에 제때 응답하고 결정이 흔들리지 않는가 | 10Hz 연속 틱의 모델 시간과 관측→명령 적용 시간, 100ms deadline 초과율, 관측 나이, 명령 거절·폐기와 외란 후 회복, 결정 전환율·왕복 전환 |
| 확률의 활용 | 질문에 맞는 확률이 실제 라벨과 일치하는가 | NLL/Brier, 보정과 분포 변화에서의 오류 |
| 시스템 성과 | 고정 하네스에서 모델이 규칙 기반 판단기보다 로봇 작업에 기여하는가 | 규칙 기준군 대비 자율 성공률(기하 충분 층·의미 판단 층 분리), 센서부터 명령까지 지연, 회복·완료시간 |

`N`은 독립된 상태 수, `Q`는 상태 하나에 대한 질문 수로 구분한다. **단일 로봇의 새 상태 한 건에 여러 질문을 넣는 `N=1, Q>1`이 핵심 평가 조건**이다. `N=1, Q=1`도 단일 질문 비교 조건으로 포함한다. 큰 `N`의 오프라인 처리량만으로 반응성 개선을 주장하지 않는다.

기존 계획서의 p95 지연 2배 이상 개선과 성공률 비열등 한계 −3%p는 잠정 기준이다. 같은 질문 묶음·하네스를 사용하는 품질 자격 기준군을 분모로 정하고, 파일럿 이후 최종 시험 전에 판정 규약을 동결한다. 로봇 성공률은 paired 에피소드 차이의 95% 신뢰구간으로 평가하며 표본이 부족하면 유보한다.

모델 실행시간, 질문 묶음이 준비된 뒤 답을 받기까지의 시간, 하네스 조합을 거쳐 명령이 준비되는 시간, 센서부터 실행기 접수까지의 시간을 나눠 보고한다.

## 8. 공정한 비교와 연구 범위

기반 모델 규모·초기 체크포인트, GPU·정밀도, 입력 정보, 질문·후보, 하네스 조합 규칙과 실행기를 맞춘다. 비교군에도 공통 상태 캐시, batching과 효율적인 출력 표현을 허용한다.

질문별 최소 라벨 출력, 직접 라벨 점수 읽기, 질문 묶음의 최소 구조화 출력 등을 기준군으로 둔다. 같은 질문을 순차 처리하거나 병렬 처리하는 경로, 공통 상태 공유의 유무를 비교한다. 한 행동 ID만 출력하는 모델과 여러 판단 분포를 반환하는 모델의 지연을 그대로 같은 기능의 비교로 취급하지 않는다.

동일 가중치에서 실행 방식만 바꾸는 비교와, 동일 초기 체크포인트·데이터·예산에서 구조별 후속 학습을 수행하는 비교를 분리한다. 폐루프에서는 같은 하네스에 규칙 기반 판단기를 넣은 기준군을 포함해 하네스만으로 해결되는 범위를 먼저 잰다. 그 기준군이 포화하는 조건에서는 모델의 기여를 주장하지 않는다. 하네스가 추가로 해결한 판단, 후보 생성의 정보·비용과 결과 조합 규칙을 공개한다. 기존 행동정책과 전체 시스템을 비교할 때에는 모델 구조의 인과적 효과와 별도로 보고한다.

| 구분 | 내용 |
| --- | --- |
| 핵심 개발 | 다양한 질문·후보를 해석하는 병렬 판단 모델, 직접 확률 출력, 상태 공유, 질문 분기, 학습과 보정 |
| 첫 응용 검증 | 단일 팔·평행 그리퍼의 테이블톱 작업에 대해 결합 행동 후보의 주 결정과 게이팅 판단을 조합. 규칙 기반 기준군과 조건 층별로 비교 |
| 데이터 설계 | 로봇 상태를 과반으로 두고 rollout에 근거한 라벨을 확대. 비로봇 분야는 일반화 평가에 필요한 만큼 유지 |
| 후속 확장 | 더 많은 질문·후보, 다른 응용 하네스, 지원 명세에 따른 연속 수치 직접 예측 |
| 별도 범위 | 소형 학생 증류, 양자화·가지치기에 의한 가속, 엣지 탑재, 전용 MoE 신규 사전학습 |

새 질문의 이름만 바꾼 성능, 새로운 후보 조합, 새로운 질문 의미, 새로운 분야로의 전이를 구분한다. 특정 분야에서 좋은 결과가 나왔다고 모든 내용에 대한 신뢰성을 확보했다고 가정하지 않는다.

## 9. 기대 결과물과 다음 설계

산출물은 모델 계산 그래프와 학습된 체크포인트, 질문 묶음 데이터 생성·검증 코드, 학습·평가 코드, 데이터 명세와 공개 가능한 평가셋, 원시 프로파일, 고정 하네스와 로봇 데모, 기술 보고서다. Matrix 없이도 대표 실험을 실행할 기본 인터페이스를 제공한다. 가중치·데이터 공개는 사용 권한에 따른다.

[대표 작업과 학습 문제 정의](02-task-and-learning-problem.md)는 첫 로봇 하네스의 요청과 실행을 설명하고, [스트리밍 계약](08-streaming-io-and-data-contract.md)은 그 입출력·조합 규칙·컨트롤러·라벨·레코드를 정본으로 정의한다. [모델 설계](03-model-and-training-design.md)는 backbone·분기 attention·readout·학습 가중치를, [데이터 계획](04-data-generation-plan.md)은 생성과 검증을, [실행 계획](06-execution-roadmap.md)은 최초 checkpoint까지의 구현 순서를 구체화한다.

기존 계획서의 12주·4인 역할 구성과 초기 5천 건에서 5만 건 이상으로의 데이터 확대는 예산 참고안이다. 상태 수·질문 수·에피소드 수를 따로 집계하며, 새 데이터 단위와 학습 곡선에 맞춰 예산을 다시 산정한다.

로봇용 질문 구성, 데이터 생성, 모델 구조·학습과 평가 규약은 이 프로젝트가 검증할 연구 설계다.
