# 병렬 판단 모델 연구 문서

이 폴더에서 모델 구조, 데이터 생성, 실제 학습과 평가 계획을 정리한다. [개발 계획서 v2](../Steerix_Robotics_Jev_Development_Plan_v2.docx)를 출발 자료로 삼으며 현재 연구 방향은 아래 문서에 반영한다.

**하네스가 상태·분야별 질문·타입·후보를 구성하고, 모델은 여러 질문의 선택·확률·점수를 병렬로 반환한다. 하네스가 답을 조합해 실행한다.** 모델이 질문과 후보를 생성하는 역할까지 맡지는 않는다.

직접 개발할 범위는 모델 구조, 학습 데이터 생성 파이프라인, 실제 학습·체크포인트, 판단 평가와 로봇 폐루프 검증 전체다. 로봇은 첫 응용이며 질문 의미와 후보를 특정 행동 목록에 고정하지 않는다.

## 현재 실행 방향

1. 요청·라벨 계약과 수동 검수한 64상태를 먼저 만든다. 로봇 상태에는 결합 행동 후보의 주 결정을 포함한다.
2. 로봇 판단 주기의 지연 예산에서 backbone 규모의 상한을 역산하고, 후보(첫 후보 Qwen3.8-27B, 소형 dense·MoE·full-attention 후보)의 연속 틱 지연과 무학습 품질을 실측해 본 실험 backbone을 확정한다.
3. D1(비로봇 단일 요청 2,000 상태 + 로봇 스트림 400 에피소드, 스크립트 전문가·규칙·키프레임 rollout 라벨)을 생성하고, 선정한 backbone으로 실제 학습(스트림은 truncated BPTT)·저장·재개를 검증한다. readout은 결정 위치 pointer 방식이며 후보별 분기 readout은 추가 연산을 쓰는 비교군이다.
4. 같은 backbone에서 50K 데이터·상태 공유 구조·여러 seed의 비교로 확대한다. 일반 attention과 DeltaNet 양쪽의 분기 격리·gradient를 검증하고, 상태 선행·질문 선행 배치를 비교한다.
5. 단일 상태의 여러 질문과 연속 틱의 품질·지연을 확인하고, 규칙 기반 판단기 기준군과 결정 안정성 지표를 포함한 고정 로봇 하네스의 폐루프 성과와 연결한다.

모델·시뮬레이터·클라우드 구성은 제안이며 장비·계정·예산은 아직 확정하지 않았다. 구현은 브랜치 `task-1-contracts`에서 [06](06-execution-roadmap.md)의 Task 순서로 진행 중이며, 각 Task의 상태는 구현·단위 검증·폐루프 인수·학습 실측의 네 단계로 나눠 아래에 기록한다. 통과하지 않은 단계는 주장하지 않는다.

같은 날의 첫 검토에서 지적한 P0/P1 기준 예산·일정 재산정과 기준군의 2×2 재구성(출력 방식 × 공유 유무)은 위 변경으로 일부만 해소되었고 아직 반영하지 않았다.

같은 날 OM-1의 비동기 계층 구조를 검토한 뒤 robojev의 계층을 "의미에 대한 System 1"(L2)로 정의하고, 전술·그리퍼 상태·정지·거친 운동 의도를 10Hz 스트리밍 typed 출력으로 내는 입출력·데이터 계약을 [08](08-streaming-io-and-data-contract.md)에 합의했다. [리뷰 09](09-streaming-contract-review.md)의 S1~S7(L1-a 격리 계약, truncated BPTT, commitment 기준 부가 출력, 그리퍼 상태 출력, 명령 수명, 라벨 규칙, DAgger 이력 보존)을 08에 반영했다. 이어 08의 11절 목록에 따라 01~06의 로봇 부분(계층·스트림 모드·격리 예외, 첫 작업·질문 세트 v0·조합 규칙·컨트롤러 계약, L1-a 배치·TBPTT·부분 라벨 손실, 에피소드 레코드·D1 규모·rollout 예산·라벨 규칙, 10Hz·50Hz·명령 수명 지표, Task 구성)을 교체했다. 충돌하는 세부는 08이 정본이다. 이어 앞단을 "공통 구조화 스키마를 채우는 교체 가능한 모듈"로 정의하고 실로봇의 주 앞단을 3D 카메라 → 3D 재구성으로 두어, 08(3D 요약 필드·소스별 관측 나이·`geom[]` 슬롯·기하 나이 허용), 05(E2/E3 경로), 06(`perception/` 모듈), 01·03(Physical State → typed Action)을 갱신했다. 마지막으로 07의 R4~R6과 첫 검토의 예산 재산정을 반영했다: 비용 표현 정정(03 §3, 01 §6), 출력 방식 × 공유 유무의 2×2 실험표와 6 checkpoint 정의(03 §5·§6), 2단계 backbone 선정 게이트(06 Task 2b, 05 G0a/G0b), 스트림 기준 시간 풀 재산정(05 §6: 9B는 seeds까지 264 node-hours 안, 27B는 seeds 없이 1~3순위까지). 미반영 항목은 없다.

구현 뒤의 [리뷰 10](10-current-implementation-review.md)(I1~I6, 모두 재현·타당)과 그 원인 추적(고정 시점 배치, 파지 접근 중 팔의 자기 가림으로 후보 소실·관측 분기 반복)을 반영해 08의 계약을 보강했다: 전환 틱 초기 경로는 "막히지 않은 경로", 하네스는 실제 명령 구간을 장애물에 대조, 국면별 목표점(lift 수직 상승·transport 높이 유지) 정의, 기하 나이는 적용 시각 기준(`geometry_observed_at`)이며 파지·놓기 국면과 파지 중에는 readiness가 대신함, 실행 가능성은 가시 비율이 아니라 기하 나이로, 파지 중 물체 자세는 고유 감각에서, 물체 이동 사건은 관측된 변위에서만, `q_instr`은 지시 텍스트의 문제·`q_observe`는 대상 미관측 포함, 관측은 관측 자세로 이동 후 대기(02의 `OBSERVE` 정의도 수정). 코드 반영은 Task 3b 수정 라운드다.

가설·잠정 목표·측정 결과를 구분한다. 하네스가 구성할 내용과 모델이 학습할 내용을 분리하고 각각의 버전을 기록한다.
