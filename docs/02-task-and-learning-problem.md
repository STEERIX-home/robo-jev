# 첫 로봇 하네스와 모델 학습 문제 정의

작성일: 2026-09-18

문서 상태: 연구 설계 초안. 장비는 미정이며 단일 로봇팔·평행 그리퍼를 기준으로 한다. 대표 작업과 아래 질문·후보·실행 규칙은 초기 제안이다. 같은 날 근본 검토를 반영해 주 결정을 결합 행동 후보의 선택으로 바꾸고, 규칙 기반 판단기 기준군과 결정 안정성 지표를 추가했다. 이어 [스트리밍 계약](08-streaming-io-and-data-contract.md)에 따라 첫 작업, 10Hz 스트림, 질문 세트 v0, 조합 규칙·컨트롤러 계약, 라벨 계약을 교체했다. 충돌하는 세부는 08이 정본이다.

이 문서는 [연구 컨셉과 목표](01-research-concept-and-goals.md)를 첫 로봇 응용에 연결한다. **하네스가 상황별 상태·질문·타입·후보를 구성하고, 모델은 여러 질문을 병렬로 판단한다.** 하네스가 반환된 선택·확률·점수를 조합해 실행 명령을 만든다. 질문과 후보를 구성하는 능력은 이 판단 모델의 학습 목표에 포함하지 않는다.

## 1. 첫 대표 작업

첫 작업은 **어수선한 다물체 정리**다. 물체 6~10개(취약·금지 속성 포함)와 목표 영역이 있는 테이블에서 지시에 따라 물체를 집어 옮기거나 밀어 치운다. 에피소드 도중(5~15초 사이)에 지시가 바뀌고, 일부 물체는 외란으로 움직인다. 이 구성은 전술(무엇·어디)과 운동 의도(어떻게·언제) 양쪽에서 결정이 촘촘하게 생기도록 고른 것이다. 정적인 집기·옮기기만으로는 판단 계층의 기여가 드러나지 않는다.

환경은 한 팔, 평행 그리퍼, 고정 테이블, 집거나 밀 수 있는 단단한 물체, 목표 영역과 보호 장애물로 시작한다. 정적인 집기·옮기기로 입출력을 점검한 뒤 위치 변화·외란, 접근 방해, 지시 변경, 실패 이력, 밀기와 부분 관측을 차례로 추가한다. 각 조건은 별도로 평가한다. 사람과의 핸드오버·양보와 양팔 분담은 후속 작업이다.

평가 조건은 **기하만으로 충분한 조건**과 **의미 판단이 필요한 조건**으로 층을 나눈다. 후자는 모호하거나 바뀌는 지시, 우선순위와 허용 접촉의 변경, 실패 이력에 따른 대응, 부분 관측에서의 정보 수집처럼 후보의 기하 비용만으로는 답이 정해지지 않는 상황이다. 하네스가 후보 생성과 충돌 검사를 마치면 단순한 집기·옮기기는 규칙 기반 순위로도 풀릴 수 있다. 그래서 9절의 규칙 기반 판단기 기준군으로 각 층의 포화 여부를 먼저 확인하고, 모델의 기여는 두 층을 나눠 보고한다.

특정 로봇 제품·시뮬레이터는 아직 선정하지 않는다. 물체의 크기·질량·마찰, 구간 길이와 제어 제한은 선택한 장비의 작업 프로파일로 고정한다. 첫 작업은 모델의 의미 범위를 고정하는 목록이 아니라 하네스를 통한 검증 환경이다.

## 2. 하네스가 구성할 입력

하네스는 상태 `S_t`와 질문 묶음 `Q_t`를 만든다. 하나의 상태에는 여러 질문을 넣을 수 있고, 질문마다 다른 타입과 후보·기준을 지정한다. 질문 수와 항목 이름은 요청에 따라 달라진다.

| 상태의 요소 | 포함할 내용 | 정보의 경계 |
| --- | --- | --- |
| 목표·제약 | 대상, 목표 영역, 우선순위, 허용·금지 접촉과 지시 | 모든 비교군에 같은 과제 정보 제공 |
| 물체·장면 | ID·설명·형상, 위치·자세, 장애물·목표 영역 | 관측 시각·불확실성·알려지지 않은 값 명시 |
| 로봇 상태 | 말단 자세, 그리퍼 폭, 현재 명령과 진행 정보 | 실제 관측 또는 선언한 추정치만 사용 |
| 최근 이력 | 관측, 선택·실행 행동, 완료·실패·중단 피드백 | 이력 길이·요약 규칙을 비교군에 동일하게 적용 |
| 실행 가능 정보 | 등록된 기능, 자세·경로·프로파일 후보, 단위·제약 | 하네스의 후보 생성 규칙·비용·정보 출처 기록 |

초기 참조 상태 실험은 현재 시점의 지정된 시뮬레이터 정보를 사용할 수 있다. 미래 결과와 후보 실행 결과는 라벨에만 사용한다. 이후 시뮬 3D 카메라 → 3D 재구성 → 고정 추출 모듈(E2), 실제 3D 카메라(E3)의 관측으로 검증하며 조건을 분리한다. 어느 앞단이든 같은 구조화 스키마를 채우고, 정밀도·가시성·소스별 관측 나이·결측으로 품질 차이를 표현한다. 부분 관측 조건에서는 가려진 물체의 최신 참값을 입력에 넣지 않는다.

하네스는 관측과 로봇 제약으로 후보를 만들고 질문에 그 의미를 설명한다. 정답을 알고 후보를 제거·정렬하지 않는다. 모델에는 제공된 후보를 판단할 책임이 있고, 하네스에는 판단에 필요한 정보와 유효한 선택 범위를 구성할 책임이 있다.

## 3. 한 상태에 함께 넣을 질문의 구성

첫 로봇 하네스는 **매 틱(10Hz) 같은 9개 질문**을 병렬로 묻는다. 대상·접근·프로파일처럼 서로 결합된 선택은 독립 질문으로 나누지 않는다. 하네스가 유효한 조합을 **결합 행동 후보**로 만들어 한 목록으로 묻고, 그리퍼 상태·정지·경로·속도·힘도 같은 세 판단 형태의 질문으로 낸다. 각 결합 후보는 그대로 실행할 수 있는 짧은 행동이다. 질문 세트는 하네스 버전으로 고정하고 후보는 틱마다 바뀐다. 정본은 [스트리밍 계약](08-streaming-io-and-data-contract.md) 4절이다.

| ID | 질문 | 판단 형태 | 하네스가 제공할 후보·기준 | 참조 대상 | 결과 사용 |
| --- | --- | --- | --- | --- | --- |
| `q_main` | 지금 실행할 행동은 무엇인가 | 선택 | 기능(grasp/place/push)·대상·접근 또는 접촉·목적지·운동 프로파일을 묶은 결합 후보와 관측·보류·재계획 후보. 후보마다 `action_ref`, 의미 설명, 하네스가 계산한 기하 값. K≤32 | 현재 틱 | 목표·모드 결정 |
| `q_done` | 현재 목표를 이미 만족했는가 | 이진 판단 | 관측 가능한 목표 조건 | 현재 목표 버전 | 완료 확인 절차로 분기 |
| `q_instr` | 실행에 필요한 지시가 충분한가 | 이진 판단 | 대상·목표·제약의 완결성 기준 | 현재 목표 버전 | 부족하면 재계획·질의로 분기 |
| `q_observe` | 관측을 더 얻어야 하는가 | 이진 판단 | 현재 관측의 나이·가림·필요 정보에 대한 기준 | 현재 틱 | 재관측 분기 |
| `q_retry` | 직전 실패와 같은 방식의 재시도가 적절한가 | 이진 판단 | 실패 이력과 재시도 기준 | 현재 틱 | 같은 방식 후보의 실행 조건 |
| `q_stop` | 지금 즉시 멈춰야 하는가 | 이진 판단 | 사람·충돌·낙하 위험, 잘못된 행동 진행 | 현재 틱 | 최우선 정지 |
| `q_gripper` | 원하는 그리퍼 상태 | 선택 | open / closed | 틱 시작 시 commitment와 국면 | 실행기가 상태 변화를 이벤트로 변환 |
| `q_path` | 경로 | 선택 | direct / via W1..Wn(n≤3, 하네스 국소 플래너) / retreat / hold | 틱 시작 시 commitment와 국면 | 명령의 경로 |
| `q_speed` | 속도 수준 | 수준 평가 | 0 / 0.1 / 0.25 / 0.5 m/s | 틱 시작 시 commitment와 국면 | 속도 상한 |
| `q_force` | 접촉·힘 수준 | 수준 평가 | 회피 / 가벼운 접촉 / 밀기 | 틱 시작 시 commitment와 국면 | 임피던스·접촉 허용 |

부가 질문 네 개(`q_gripper`·`q_path`·`q_speed`·`q_force`)는 틱 시작 시 확정된 commitment(`action_ref`와 국면)에 대한 답이다. 주 결정이 바뀐 틱에는 이 답을 폐기하고 새 후보의 초기 프로파일을 적용한다. 의도·대상 진단 질문은 오류 분석용으로 별도 요청에서 물을 수 있으며 매 틱의 세트에는 넣지 않는다.

기하 계산은 하네스가 맡는다. 도달 가능성, 충돌 여유, 거리, 파지 폭처럼 고전적인 계산으로 정확히 얻을 수 있는 값은 하네스가 계산해 후보 설명에 넣는다. 한 번의 forward로 답하는 모델은 여러 단계의 수치 계산에 약하므로 좌표만 주고 기하 판단을 맡기지 않는다. 모델에는 지시와 제약에 맞는 선택, 우선순위의 조정, 이력에 따른 전술, 정보의 충분성처럼 의미와 문맥에 달린 판단을 묻는다. 하네스가 제공한 파생 값과 그 계산 규칙은 입력 버전으로 기록하고 모든 비교군에 동일하게 제공한다.

결합 후보의 수는 요청의 상한 안에서 관리한다. 첫 프로파일의 상한은 32개이고 보통 12개 안팎이다. 실행 가능한 조합이 상한을 넘으면 하네스가 정답을 모르는 채로 적용할 수 있는 규칙(도달 불가 조합의 제거, 기하적 다양성 표본)으로 줄이고 후보 포함률을 기록한다. 상한으로도 담을 수 없는 장면은 대상 범위를 좁히는 선행 호출을 두고 그 비용을 포함해 평가한다. 조합 폭발은 질문 수에서 후보 수로 옮겨진 것이며 없어진 것이 아니다.

**분해형 구성은 비교군으로 둔다.** 의도, 대상, 목표 영역, 대상별 접근(“A를 집는다면”, “B를 집는다면”), 프로파일을 각각 질문으로 나누고 조건에 맞는 답만 사용하는 방식이다. 조건을 요청에 넣으면 모델이 대상 선택의 답을 기다릴 필요 없이 병렬로 판단할 수 있다는 장점이 있다. 그러나 질문 수가 물체 수와 선택 단계의 곱으로 늘고, 답을 합치는 규칙을 사람이 작성해야 한다. 같은 모델·상태에서 결합형과 분해형의 판단 품질, 틱당 토큰, 폐루프 성과를 비교한다. 이는 모델을 바꾸는 비교가 아닌 하네스 구성의 비교로 보고한다.

물체·도구·목표·실행 기능이 바뀌면 하네스가 다른 질문과 후보를 넣는다. 모델은 그때 제공된 내용에 반응하도록 학습한다. 후보 ID와 질문 이름의 암기 성능과 새로운 질문 의미에 대한 일반화는 구분한다.

## 4. 하네스의 결과 조합과 실행기 기능

모델의 응답은 질문별 판단 결과의 묶음이다. 하네스는 틱마다 아래 순서로 답을 적용하고 충돌 건수를 기록한다. 정본은 [스트리밍 계약](08-streaming-io-and-data-contract.md) 5절이다.

| 순서 | 구성 단계 | 하네스가 할 일 | 모델과 구분해 기록할 내용 |
| --- | --- | --- | --- |
| 0 | 유효성 검사 | 응답의 관측 시각이 deadline(200ms) 안이고 목표 버전·후보 집합 버전·요청 순번이 현재와 일치할 때만 진행. 아니면 폐기 | 폐기 건수와 사유 |
| 1 | 반사·정지 | 실행기 반사 또는 `q_stop`이 참이면 혼합을 우회한 정지 전이. 다른 답은 이 틱에 적용하지 않음 | 정지 빈도, 오경보 |
| 2 | 게이팅 | 목표 만족 → 완료 절차, 지시 부족 → 재계획·질의, 재관측 필요 → 관측(운반 중이면 보류 후 관측). 발동 시 commitment 해제 | 게이팅 임계값, 우선순위, 주 결정과의 충돌 건수 |
| 3 | 주 결정과 결정 유지 | `q_main`의 선택 후보에 히스테리시스 적용 | 전환 여유 `δ`, 연속 틱 수 `m`, 전환·해제·유지 기록 |
| 4 | 부가 답 적용 | commitment가 유지된 틱에만 경로·속도·힘·그리퍼 답을 그 commitment의 프로파일·제약 안에서 적용. 전환 틱에는 폐기하고 초기 프로파일 | 폐기 건수, 제약에 의한 상한 적용 |
| 5 | 그리퍼 이벤트 | 원하는 상태가 현재와 다르면 readiness 확인 후 이벤트를 한 번 발생시키고 ACK | 이벤트 ID, 대기·누락·중복 |
| 6 | 명령 생성 | 순번·관측 시각·목표 버전·`action_ref`·국면·lease를 붙여 명령 생성. 충돌·도달·전환 구간 검사에 걸리면 거절 | 거절 사유, 전환 구간 검사 결과 |

여러 답이 충돌하면 임의로 결합하지 않고, 미리 정한 규칙에 따라 다시 관측·질문하거나 실행을 보류한다. 확률을 조합하는 규칙도 명시하며 선택 분포를 물리적 성공 확률로 곱하지 않는다. 하네스가 도메인 규칙으로 해결한 부분은 시스템의 기여로 보고한다.

결정 유지 규칙의 첫 값은 다음과 같다. 현재 실행 중인 후보가 이번 틱의 목록에 남아 있으면 그 후보를 계속 쓰고, **같은 도전자**의 확률이 현재 후보보다 `δ=0.15` 이상 높은 상태가 `m=2` 틱 연속될 때만 바꾼다. 도전자가 바뀌면 카운터를 초기화한다. 목표 버전 변경, 행동 완료, 현재 후보 무효화, 게이팅 발동 시에는 commitment를 해제하고, 정지가 `m` 틱 이상 이어져도 해제한다. 후보의 동일성은 별칭이 아니라 **기능·대상·접근 유형·목적지·프로파일**의 의미 키로 판정하고 연속 파라미터는 허용 오차로 비교한다. 현재 commitment와 진행 정보는 상태의 실행 이력에 들어가므로 모델도 이를 본다. `δ`와 `m`은 시작값이며 개발용 폐루프에서 전환율과 반응 지연의 교환으로 조정한다. 모든 비교군에 같은 규칙을 적용한다.

**컨트롤러 계약.** 명령은 `seq`, 관측 시각, 발행 시각, lease(발행 + 300ms), 목표 버전, `action_ref`·국면, 경로, 속도 상한, 접촉·힘 수준, 원하는 그리퍼 상태, 정지 플래그를 담는다. 실행기는 새 명령을 100ms 동안 혼합해 전이하고, lease가 끝나면 감속 정지하며, 정지·반사 시에는 혼합을 우회한다. 관측 deadline과 발행 lease를 따로 검사하고 순번이 역행한 명령은 폐기한다. 큐를 쌓지 않고 최신 관측으로 다음 틱을 만든다. OSC 말단 목표 갱신은 50Hz, 토크 계산과 물리는 500Hz다. 전체 계약은 08 6절이다.

첫 워크셀에서 등록할 실행 기능은 다음과 같이 제안한다. 모델의 고정 클래스 목록과는 구분한다. 스트림 명령과의 대응은 `MOVE_EE` ← 경로·속도·힘, `SET_GRIPPER` ← 원하는 그리퍼 상태의 변화, `PUSH_SEGMENT` ← push 결합 후보의 경로·힘, `OBSERVE`·`HOLD`·`REQUEST_REPLAN` ← 게이팅·정지·보류 후보다.

| 실행기 등록 예시 | 실행할 기능 | 명령 값의 구성 |
| --- | --- | --- |
| `MOVE_EE` | 지정한 짧은 구간의 보간·IK·말단 목표 추종 | 선택된 결합 후보의 대상·접근·운동 프로파일을 하네스가 목표 자세에 매핑 |
| `SET_GRIPPER` | 팔 자세를 유지하며 정해진 한계 내 그리퍼 구동 | 선택된 열기·닫기 또는 폭 프로파일에 매핑 |
| `PUSH_SEGMENT` | 접근이 끝난 접촉 위치에서 짧은 밀기 구간 추종 | 선택된 접촉·방향·거리 후보에 매핑 |
| `OBSERVE` | 정지 상태에서 제한된 기간 새 관측 대기 | 하네스가 관측 분기와 고정 프로파일 선택 |
| `HOLD` | 정해진 정지·유지 절차 수행 | 보류 조건에 따라 실행하며 자동으로 물체를 놓지 않음 |
| `REQUEST_REPLAN` | 상위 작업 지능에 재계획 요청 | 하네스의 분기 결과로 요청하고 자율 완료와 구분 |

실행기는 받은 명령의 추종을 담당한다. 새로운 접근 전략과 복구 행동은 다음 판단과 하네스 조합으로 정한다. 좌표계 변환·IK와 작업 의미를 판단하는 로직의 경계를 기록한다.

최종 명령에는 행동 ID, 대상, 좌표계, 파라미터, 유효 조건과 종료 조건이 들어간다. 요청·관측·후보 버전은 하네스가 부착한다. 첫 실험의 위치는 m, 각도는 rad, 시간은 s, 자세 표현은 로봇 기준 좌표계의 위치와 quaternion을 사용하도록 제안한다. 이것은 하네스와 실행기의 계약이며 모델이 매번 그 전체 레코드를 생성해야 한다는 요구가 아니다.

## 5. 병렬 질문과 의존성

**한 상태에서 질문을 미리 정의할 수 있으면 함께 묻는다.** 서로 결합된 선택은 하네스가 유효한 조합을 결합 행동 후보로 만들어 한 질문에 담는 방식을 기본으로 한다. 조건을 명시한 분해형 질문(“A를 집는다면”)은 비교 구성과, 결합 후보가 상한을 넘는 장면의 보조 수단으로 둔다. 질문과 후보를 얼마나 펼칠지는 토큰·후보·계산 예산으로 제한하며, 모든 조합을 무제한으로 나열하지 않는다.

첫 답으로 새로운 관측이나 후보를 얻어야 하는 경우에는 다음 호출이 필요하다. 예를 들어 선택된 도구의 정보를 뒤늦게 조회해야만 다음 질문을 만들 수 있다면 그 정보가 온 뒤 다시 판단한다. 질문을 만들 수 있는데도 앞선 출력 생성이 끝날 때까지 기다리는 순차 의존은 줄인다.

같은 요청의 질문끼리 아직 나오지 않은 답을 전달하지 않는다. 질문 안의 조건과 후보는 모두 그 요청의 입력에서 정해져 있어야 한다. 서로 강하게 연결된 선택은 결합 후보로 묻는다. 조건별 질문으로 풀어내는 구성은 비교군이며, 어느 구성이든 모델 비교군에는 동일하게 제공한다.

## 6. 상태 갱신과 주 평가 조건

기본 흐름은 `관측 → 하네스의 상태·질문 묶음 구성 → 모델의 병렬 판단 → 하네스의 답 조합·검증 → 실행 → 다음 관측`이다. 이동 구간의 갱신과 접촉 동작의 중단 절차는 고정 실행기 프로파일로 관리한다.

새 프레임이 도착했다는 이유만으로 모든 응답을 폐기하지 않는다. 원래 요청에 답을 연결하고 관측 나이·목표·기하 조건이 유효한지 검사한다. 만료된 후보를 최신 후보 목록의 같은 인덱스로 해석하거나 실행 목표를 임의로 보정하지 않는다. 거절률과 재요청 비용도 측정한다.

모델 판단 주기와 하위 제어 주기는 구분한다. 폐루프에서는 실제 지연 또는 명시한 지연 모델을 반영하며, 모델 계산을 기다리는 동안 시뮬레이션 시간을 멈춰 반응시간 비용을 없애지 않는다.

로봇 폐루프에서는 같은 질문 세트를 매 틱(10Hz) 다시 묻고 상태만 바뀐다. 에피소드 하나가 append-only 토큰 스트림이고, 지시·제약·질문 세트를 prefix에 둔 뒤 틱마다 전체 상태·실제 실행 이력·동적 후보와 9개 결정 위치를 붙인다. 결정 위치는 틱 끝 공통 상태에서 갈라지는 일시적 분기이며, 다음 틱은 분기 이전의 공통 상태에서 이어간다. 이 배치는 [모델 설계](03-model-and-training-design.md)의 L1-a이고 구조·윈도우·검사는 [스트리밍 계약](08-streaming-io-and-data-contract.md) 3절이 정본이다. 판단 주기의 모델 시간 예산은 지연 예산 산식으로 정하고, 10Hz 목표는 실측한 100ms deadline 초과율로 판정한다.

매 틱 독립적으로 판단하면 결정 경계 근처에서 선택이 A→B→A로 오갈 수 있다. 4절의 결정 유지 규칙으로 이를 억제하고, 9절의 결정 안정성 지표로 측정한다.

`N=1`은 현재 로봇 상태 한 건, `Q`는 그 상태에 대한 질문 수다. **매번 갱신된 상태에 여러 질문을 넣는 `N=1, Q>1`이 주 실험**이며 첫 하네스에서는 `Q=9`의 연속 틱이다. `Q=1`은 단일 질문 비용과 품질을 확인하는 비교 조건이다. 큰 `N`의 오프라인 처리량과 단일 로봇의 판단 묶음 지연을 구별한다.

## 7. 직접 생성할 학습 데이터

모델의 학습 단위는 **상태와 하네스가 구성한 질문 묶음, 질문별 라벨**이다. 최종 행동 라벨 하나만으로 모든 질문을 같은 방식으로 감독하지 않는다. 로봇 데이터의 독립 단위는 에피소드 스트림이며 틱은 상관된 표본이다. 레코드 정의는 [스트리밍 계약](08-streaming-io-and-data-contract.md) 8절이 정본이다.

```text
단일 요청: D = {state, questions, per_question_labels, provenance}
스트림:    E = {prefix, ticks[{state, exec_history, candidates, model_output, adopted, ack, labels}], provenance}
추가 기록 = {하네스·컨트롤러·전문가·규칙 버전, 관측·실행 시각, 실제 사용된 답, 실행 결과}
```

1. **분할을 먼저 정한다.** 에피소드·장면·목표 계열과 질문 의미·후보 조합·응용 분야를 holdout 축으로 정의한다. 같은 상태의 질문 증강과 후보별 실행은 같은 분할에 둔다.
2. **상태와 문제를 생성한다.** 시뮬레이션·실행 로그·사람 시연과 명세에 근거해 목표·상태·이력을 만든다. 다양한 질문 의미를 확보할 별도 판단 데이터의 범위와 비중도 설계한다.
3. **하네스 형식의 요청을 구성한다.** 데이터 생성 코드가 질문·타입·후보·기준을 만들고, 질문 수·종류·순서·후보 수와 조건별 분기를 다양화한다. 교사를 쓰더라도 질문 구성은 외부 데이터 파이프라인의 역할이다.
4. **질문별 라벨을 만든다.** 명제와 수준 평가는 명시한 판정 기준에 근거한다. 주 결정의 결합 후보는 (1) 지시·목적지·금지 조건의 **의미 적합성**을 먼저 산출하고, (2) 적합 후보 안에서만 실행 성과(키프레임의 rollout 성공률, 그 외 틱은 플래너 비용)를 비교하며, (3) 현재 commitment가 적합하고 성과가 허용 여유 안이면 유지를 정답으로 둔다. 근거가 약하면 복수 허용·추가 rollout·낮은 라벨 신뢰도로 처리하고 rollout하지 않은 후보는 미확인으로 둔다. 부가 질문의 라벨은 그 틱의 실제 commitment에 조건화한 전문가 답이고, 그리퍼는 원하는 상태(전환 ±1틱만 두 상태 허용), 정지는 허용 지연 없음, 힘은 전문가의 목표 접촉 모드다. 규칙은 [스트리밍 계약](08-streaming-io-and-data-contract.md) 7절이 정본이다.
5. **요청과 라벨을 검증한다.** 후보 포함률, 의미의 모호함, 여러 유효 답, 참조·타입·단위 정합성과 미래 정보 누수를 검사한다. 근거가 부족한 라벨은 미관측·불확실로 남긴다.
6. **묶음과 폐루프 실패를 보강한다.** 여러 질문을 함께 넣었을 때의 오판·분기 불일치와 실행 실패를 수집한다. 같은 상태에 대한 단독·묶음 요청을 만들어 품질과 정합성을 비교한다. 같은 현재 관측에 다른 이력과 현재 실행 중인 후보를 붙인 대조 상태, 관측 잡음 범위 안의 변형 쌍도 포함해 결정 유지와 안정성을 학습·평가한다. 학습 버전마다 모델을 시뮬레이션에서 실행해 방문한 틱을 전문가·규칙으로 다시 라벨하되(DAgger식), 입력의 실행 이력·commitment는 실제 실행된 것을 보존하고 전문가 답은 라벨에만 넣는다.

여러 선택이 유효하면 허용 집합이나 검증된 선호 분포를 기록한다. 실제로 실행하지 않은 행동의 성공 결과를 만들어내지 않는다. 교사가 말한 확신을 물리적 성공 확률 라벨로 바꾸지 않는다. 초기에는 필요한 조건별 질문에도 라벨을 붙이되, 근거가 없는 분기는 학습 손실에서 마스킹한다.

학습에서는 최종 실행에 사용되지 않은 질문도 그 자체로 올바르게 답할 수 있어야 한다. 추가·삭제된 관련 없는 질문과 후보 순서·ID 변경에 대한 정합성을 검사한다. 이름만 바꾼 증강과 새로운 의미·분야에 대한 일반화를 구분한다.

| 판단 능력 후속 학습 | 동일 규모 backbone 일부 또는 전체와 판단 헤드 | 다양한 상태·질문·기준·후보와 질문별 라벨 | 일반화 평가가 가능한 판단 체크포인트 |
| 병렬 계산 검증·학습 | 상태 공유, 질문별 분기·attention, 직접 출력, 상태 선행·질문 선행 배치 | 여러 Q·후보 수·길이의 묶음과 단독 요청 대조, 연속 틱 조건 | 묶음 품질·지연이 측정된 체크포인트 |
| 확률 평가·보정 | 판단 타입에 맞는 확률과 보정 경로 | 분리된 검증·보정 데이터와 명확한 사건 라벨 | 보정 성능과 분포 변화 평가 |
| 폐루프 보강 | 실제 오류가 발생한 판단 경로 | 고정 하네스 실행에서 수집한 실패와 교정 라벨(DAgger식, 실행 이력 보존) | 이전 버전과 비교 가능한 보강 체크포인트 |

질문별 선택·이진·수준 판단에 맞는 손실을 정의한다. 선택에는 교차엔트로피·집합·선호 손실을, 사건 확률에는 NLL/Brier 등을 검토한다. 질문 수와 타입별 빈도가 학습을 과도하게 지배하지 않도록 묶음 내 손실의 가중·정규화 방식을 정한다.

질문을 분해하거나 후보 목록을 생성하는 토큰을 정답 출력으로 학습시키지 않는다. 모델의 학습 목표는 이미 제공된 문제에 대한 판단과 확률이다. 공통 상태와 해당 질문·후보는 참조하되 다른 질문의 정답을 숨은 입력으로 사용하는 학습 누수를 막는다.

단독 호출과 묶음 호출의 의미가 같은 경로에서는 출력 정합성을 확인하고, 구조를 바꾸며 학습한 경우에는 판단 품질의 차이도 별도로 평가한다. 질문·타입별 공통 출력 경로를 연구하고 특정 질문 이름·행동마다 전용 헤드를 추가하는 구조는 지원 범위 안의 비교군으로 둔다.

생성형 비교군도 같은 초기 체크포인트·데이터·학습 예산을 사용한다. 체크포인트에는 backbone revision, 학습 계층, 데이터·하네스 버전, 손실, 시드, 자원과 평가 결과를 연결한다. 대규모 RL과 연속 수치 직접 예측은 기본 판단 모델을 검증한 뒤 별도 실험으로 검토한다.

## 9. 판단과 전체 시스템의 평가

질문별 판단 정확도·분포 품질, 후보 밖 출력과 참조 오류, 단독·묶음 정합성, 새로운 질문·후보 의미에 대한 일반화를 먼저 평가한다. 같은 체크포인트에 새로운 요청을 넣는 일반화와 시험 문제로 재학습하는 적응을 구분한다.

**규칙 기반 판단기 기준군.** 같은 하네스에서 모델 자리에 결정적 규칙을 넣는다. 입력에 구조화된 목표·제약(대상·목적지·금지)이 있으면 규칙도 그것을 똑같이 써서 적합 후보를 거른 뒤, 하네스가 계산한 기하 값의 고정 가중 비용(충돌 여유, 이동 거리, 도달 여유, 직전에 실패한 접근 유형의 감점)으로 순위를 매긴다. 게이팅·정지·그리퍼·경로·속도·힘도 규칙 임계값으로 같은 9개 답을 낸다. 규칙의 버전과 가중치는 고정해 공개한다. 이 기준군이 어떤 조건 층에서 모델과 같은 성공률을 내면 그 층에서는 모델의 기여를 주장하지 않는다. 기하만으로 충분한 층과 의미 판단이 필요한 층의 결과를 따로 보고하며, 개발용 폐루프 시험에서 두 층 모두 규칙 기준군이 포화하면 과제 조건을 다시 설계한다.

**결정 안정성 지표.** 폐루프에서는 의미 키 기준의 주 결정 전환율(상태의 유의미한 변화 없이 선택이 바뀐 틱의 비율), 짧은 창 안의 왕복 전환 횟수, 후보별 평균 유지 시간, 결정 유지 규칙이 전환을 막은 횟수를 기록한다. 오프라인에서는 관측 잡음 범위 안의 입력 변형에서 선택이 뒤집히는 비율을 잰다. 상태 변화의 유의미성 기준은 작업 명세로 고정한다. 이 지표는 성공률·완료 시간과 함께 보고하며, 낮은 전환율만으로 좋은 판단이라고 해석하지 않는다.

지연은 한 상태의 동일 질문 묶음을 기준으로 비교한다. Q·질문 타입·후보 수·입력 길이를 바꾸며 모델 시간, 전체 답 준비 시간, 하네스 조합과 명령 준비 시간을 측정한다. 질문을 순차·병렬로 처리하는 기준군과 상태 공유 없는 기준군을 포함한다. 로봇 조건에서는 같은 질문 세트로 매 틱 새 상태를 넣는 연속 틱의 모델 시간과 관측→명령 적용 시간, 100ms deadline 초과율, 관측 deadline 폐기율, lease 만료율, 컨트롤러 거절률을 측정한다. 그리퍼·정지에는 이벤트 누락률·중복률·발생 시각 오차와 `q_stop`의 지연·오경보율을 더한다.

로봇 성공은 지정한 물체가 목표 영역에서 지지면에 놓이고 그리퍼와 분리되어 정해진 기간 안정적으로 유지되며 접촉·보호 물체 제약을 만족하는 것으로 제안한다. 여유·안정 시간·허용 변위·제한 시간은 작업 명세로 고정한다. 목표 만족에 대한 모델의 답만으로 성공 처리하지 않고 별도 평가기가 판정한다.

재계획·사람 개입·강제 중단·금지 접촉·낙하·시간 초과는 별도 종료 사유로 기록한다. 보류·관측의 무한 반복을 성공으로 세지 않는다. 같은 하네스에서 모델만 바꾼 비교와, 하네스의 질문·조합 방식을 바꾼 비교는 구별한다.

실패는 정보·후보의 부족, 질문 구성의 모호함, 모델의 판단 오류, 결정 흔들림, 하네스 조합 오류, 관측·실행 오류로 나눈다. 반응시간·회복시간·완료시간과 함께 질문별 오류가 전체 행동에 미친 영향을 추적한다.

## 10. 후속 설계 문서와 연결

1. 사전학습 backbone과 규모, 판단 주기의 지연 예산에서 역산한 규모 상한, 가중치·표현 접근, 실제 학습 GPU와 예산.
2. 공통 상태·질문·기준·후보의 입력 표현과 최대 요청 크기.
3. 질문 분기 attention, 상태 공유, 질문 내 후보 상호작용과 질문 간 격리.
4. 선택·이진·수준 평가의 직접 readout과 확률 표현.
5. 질문별 손실, 묶음 샘플링, 단독·묶음 정합성과 확률 보정 방법.
6. 질문 의미·분야·후보 조합을 다양화하는 데이터 생성, 라벨 검증과 분할.

위 항목의 초기안은 [모델 구조·학습](03-model-and-training-design.md), [데이터 생성](04-data-generation-plan.md), [실험 환경·GPU](05-experiment-and-cloud-plan.md)에 구체화했다. [실행 계획](06-execution-roadmap.md)에 따라 파일럿으로 검증한 뒤 본 실험 설정을 동결한다.

모델 코드는 제공된 요청을 계산하는 구조와 학습을 담당한다. 하네스 코드는 분야별 요청 구성과 결과 조합을 담당한다. 두 부분은 버전을 분리하되 재현 패키지에서는 함께 고정한다.

## 참고와 제안의 경계

사용자가 제공한 브라우저 데모와 [공식 병렬 질문 사용법](https://docs.typesafe.ai/primitives)을 모델·하네스 역할 분리의 참고로 사용했다. 위 로봇 질문 묶음, 실행 기능과 데이터·학습 구성은 자체 설계 제안이다.

시뮬레이션 초기안은 robosuite의 [단일 팔 PickPlace 환경](https://robosuite.ai/docs/source/robosuite.environments.manipulation.html)과 [말단 목표·하위 제어기 분리](https://robosuite.ai/docs/modules/controllers.html)를 사용한다. 외란·하네스·후보별 결과 수집은 별도 구현하며, [실험 환경 계획](05-experiment-and-cloud-plan.md)의 설치·재현 검사를 거쳐 구성을 확정한다.
