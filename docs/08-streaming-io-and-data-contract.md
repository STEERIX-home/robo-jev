# robojev 스트리밍 입출력·데이터 계약 v0

작성일: 2026-09-18 · 상태: 설계 합의안(브레인스토밍 결과). 같은 날 [리뷰 09](09-streaming-contract-review.md)의 S1~S7과 세부 항목을 반영해 격리 계약, 학습 시 상태 전달, 부가 출력의 참조 대상, 그리퍼 출력, 명령 수명, 라벨 규칙을 고쳤고, 이어 앞단을 **공통 구조화 스키마를 채우는 교체 가능한 모듈**(주 앞단은 3D 카메라 → 3D 재구성)로 정의해 3D 요약 필드·소스별 관측 나이·`geom[]` 슬롯·기하 나이 허용을 추가했다. 구현 뒤 [리뷰 10](10-current-implementation-review.md)의 I1~I6와 E0 폐루프 원인 추적을 반영해 전환 틱 초기 경로, 실제 명령 구간의 장애물 대조, 국면별 목표점, 적용 시각 기준 기하 나이와 파지·놓기 국면의 예외, 기하 나이 기준 실행 가능성, 관측된 변위 기준 이동 사건, `q_instr`/`q_observe`의 귀속, 관측 자세 이동을 보강했다. 이 문서는 [연구 컨셉](01-research-concept-and-goals.md)~[실행 계획](06-execution-roadmap.md)의 로봇 부분을 대체할 입출력과 데이터 정의다. 여기 적은 수치는 시작값이며 측정 결과가 아니다. 01~06에 반영할 항목은 11절에 둔다.

## 1. 결정 요약

| 컨트롤러 | OSC 위의 스크립트 실행기에 혼합 100ms, 관측 deadline 200ms와 발행 lease 300ms, 반사와 정지 전이를 붙인다. 학습형 RL 컨트롤러는 같은 계약으로 후속 교체. |

## 2. 계층과 주기

```text
L3  작업 지능 (Astra/VLM, System 2)       초 단위, escalation 시
      ↓ 목표·제약·계획
L2  robojev (의미 System 1)                10Hz 스트리밍 + 이벤트
      ↓ 전술·그리퍼 상태·정지·경로·속도·힘 (typed, 확률)
L1  실행기 (첫 구현: OSC 스크립트, 후속: RL 컨트롤러)   50Hz 말단 목표 갱신, 혼합·반사
      ↓ 말단 목표 → OSC가 관절 토크 계산
L0  물리·모터                              500Hz
```

L2가 존재하는 이유는 실행 중에 전술이 바뀌는 상황(실패, 모호한 지시, 우선순위 변경, 움직이는 대상)에서 L3의 초 단위 지연을 100ms대로 줄이는 것이다. 전술이 바뀌지 않는 작업에서는 L2의 기여가 없어야 정상이며, 규칙 기반 판단기 기준군이 이를 확인한다.

## 3. 입력 계약

### 3.1 스트림 구조

에피소드 하나가 append-only 토큰 스트림 하나다.

```text
[prefix: 지시·제약 v1][질문 세트 v0 텍스트, 정적 후보 설명]       에피소드 시작 시 1회. 항상 보존
[틱 t 상태][실행 이력 t-1][동적 후보 t] ─┬─ [결정 위치 q_main]      공통 상태에서 10개 일시적 분기
                                         ├─ [결정 위치 q_done] …
                                         └─ [결정 위치 q_force]
[틱 t+1 상태][실행 이력 t][동적 후보 t+1] ─┬─ …                     틱 t의 공통 상태(분기 이전)에서 이어감
...
[지시·제약 v2]                                                    지시가 바뀌면 리셋 없이 뒤에 추가
```

**격리 계약.** 로봇 스트림은 [모델 설계](03-model-and-training-design.md)의 **L1-a**다. 상태 토큰은 고정 질문 세트를 이미 읽은 문맥에서 계산되므로 질문 간 격리는 성립하지 않는다. 고정 질문 세트는 하네스 버전의 조건이며, 질문 문구·후보 형식의 변경은 정합성이 아니라 품질(다른 질문의 답 변화, 폐루프 성과)로 평가한다. 요청마다 질문이 바뀌는 범용 단일 요청 경로만 L0 배치로 격리를 보장한다.

**결정 분기.** 10개 결정 위치는 틱의 `[상태][실행 이력][동적 후보]` 끝의 공통 상태에서 갈라지는 일시적 1토큰 분기다. 각 분기의 표지 토큰은 질문 세트 버전이 질문 id마다 고정해 정적 prefix에 선언한 것이며, 그 틱에 묻는 질문의 부분집합이나 순서에 따라 바뀌지 않는다(03 §3). Full-attention 층에서는 서로를 보지 못하게 mask하고, DeltaNet·conv 층에서는 공통 상태를 10개로 fork해 각 결정 토큰이 독립적으로 읽는다. 분기의 상태는 버린다. **다음 틱은 분기 이전의 공통 상태에서 이어가며**, 채택된 답은 실행 이력 토큰으로만 다음 틱에 들어간다. 여러 분기의 recurrent state를 합치는 일은 없다.

- Full-attention 층은 **정적 prefix + 최근 3초(30틱)**를 본다. prefix의 KV와 정적 후보의 hidden vector는 윈도우 밖으로 내보내지 않는다. prefix는 에피소드 시작 시의 것으로 고정이며, 도중에 추가되는 `[지시·제약 v2]`는 그 틱의 토큰이라 다른 틱 토큰과 같이 윈도우 밖으로 나간다 — 현재 지시는 매 틱 `goal` 필드가 다시 실으므로 잊히지 않는다. 학습과 추론이 같은 mask·position을 쓴다(공개 config의 전층 full attention을 바꾸는 사용자 정의 변경이므로 학습 시에도 적용).
- DeltaNet 층은 에피소드 전체 이력을 recurrent state로 유지한다.
- 리셋은 에피소드 경계에서만 한다.
- 증분 계산과 처음부터 계산의 결과가 같아야 한다. 윈도우 절단은 정의된 근사이며 그 차이를 별도 기록한다.
- 검사: 질문 하나의 문구·후보를 바꾼 뒤 (a) 다른 결정 분기의 출력 변화와 (b) 다음 틱 공통 상태의 변화를 잰다. L1-a에서는 0이 아닐 수 있으므로 품질 지표로 보고하고, 범용 L0 경로에서는 수치 오차 안이어야 한다.
- 비로봇 분야 데이터는 기존의 단일 요청 배치(L0, 상태 선행)를 그대로 쓴다. 같은 readout이 두 배치를 모두 처리한다.

### 3.2 상태 스키마 v0 (틱마다)

직렬화는 한 줄에 한 항목, 고정 필드 순서, 위치는 mm 정수, 자세는 quaternion 소수 2자리, 시간은 ms 정수로 한다. 토큰 수를 줄이기 위한 규칙이며 버전으로 고정한다.

| 필드 | 내용 | 정보 경계 |
| --- | --- | --- |
| `t` | 틱 번호, 모의 시각(ms), **소스별 관측 나이**(기하 재구성 나이, 로봇 고유 감각 나이, ms) | 기하는 10Hz보다 느리게 갱신될 수 있음 |
| `goal` | 현재 지시 텍스트와 버전, 우선순위, 금지 접촉, 목표 영역 참조 | 지시 변경은 사건으로도 기록 |
| `objects[]` | 추적 id, 설명, 자세(mm, quat)와 **정밀도 추정**(mm 오차 범위), OBB 크기(mm), 윗면 높이, 파지 가능 면, 표면 신뢰도, 가시 비율, 마지막 관측 시각, 재식별 사건, 속성(취약·금지) | 가려진 물체의 참값은 넣지 않는다. 앞단이 못 채우는 필드는 "모름"으로 둔다. 파지 중인 물체의 자세는 말단 자세에서 채운다(고유 감각, 기하 나이 0). 가시 비율은 정보이지 실행 가능성의 기준이 아니다 — 후보의 실행 가능성은 기하 나이로 정한다(팔이 대상을 가리는 파지 국면에서 후보가 사라지지 않게) |
| `scene` | 자유 공간·통로 폭 요약, 장애물 여유 지도 요약, 작업면 높이 | 3D 재구성에서 하네스가 계산 |
| `zones[]` | id, 설명, 경계 | |
| `robot` | 말단 자세, 그리퍼 폭, 파지 중인 물체, 접촉력(N), 현재 속도 | 실제 관측 또는 선언한 추정치만 |
| `exec` | 현재 명령(순번·`action_ref`·국면·경로·속도·힘·그리퍼 상태·정지), 진행률, 실행 ACK, 직전 틱 이후의 거절·반사·폐기 사건 | 실제 실행된 것만 |
| `events[]` | 외란 감지(물체 이동), 접촉 시작, 미끄러짐, 지시 변경, 그리퍼 이벤트 완료 | 하네스가 관측 가능한 원시 신호에서만 사건으로 변환. 물체 이동 사건은 **관측된 자세 변화**(두 관측 사이의 변위)에서만 만들며, 시뮬레이터의 외란 발생 사건은 evidence에만 남긴다. 가려진 물체의 이동은 다시 관측된 틱에 사건이 된다 |
| `derived[]` | 물체별: 말단 기준 상대 벡터(mm), 최근접 장애물 여유, 접근 방향별 통로 폭. 후보별: 도달 가능, 경로 충돌 여부, 거리, 파지·접촉면 참조, 대상 기하의 나이 | 하네스 계산값. **관측된 자세로만 계산**하며 가려진 참값은 쓰지 않는다. 규칙 버전 기록, 모든 비교군 동일 |
| `commitment` | 틱 시작 시 확정된 주 결정의 `action_ref`·의미 키·국면(접근/파지/들기/이동/놓기/밀기), 유지 틱 수, 마지막 전환 틱 | 부가 질문의 참조 대상 |
| `image[]` | 카메라 id와 토큰 슬롯. 시뮬레이션 단계에서는 비움 | 영상 soft token 확장 시 사용 |
| `geom[]` | 3D 재구성(점군·TSDF·메시)의 soft token 슬롯. 1차에서는 비움 | 학습형 기하 인코더 확장 시 사용 |

미래 정보, 후보 실행 결과, 정답 근거는 어느 필드에도 들어가지 않는다. serializer가 허용 필드만 통과시키고 자동 검사한다.

**앞단 조건.** 스키마의 모든 필드는 실제 앞단(3D 재구성 파이프라인)이 채울 수 있는 것으로 제한한다. 시뮬레이션에서만 얻는 정보는 넣지 않는다. 앞단은 (1) 인스턴스 분할과 틱 사이에 안정된 추적 id, (2) 소스별 관측 시각과 로봇 기준 좌표계 변환, (3) 가시성·정밀도·표면 신뢰도, (4) 후보 생성에 필요한 파지 가능 면·접촉면·자유 공간을 제공해야 한다. 3D 재구성의 갱신 주기와 지연은 기하 5Hz·100ms를 시작값으로 두고 실측으로 바꾼다. E2/E3에서는 시뮬 3D 카메라(깊이 렌더 + 잡음·결손 모델) → 같은 재구성 파이프라인 → 같은 추출 모듈로 상태를 만들어 실로봇과 분포를 맞추고, 재구성의 결함(표면 결손, 추적 id 흔들림, 지연)을 재현한다. 추출 모듈은 버전을 고정하고 모든 비교군에 동일하게 쓴다.

### 3.3 실행 이력의 재입력

틱 t−1에서 **실제로 채택·실행된** 답(주 결정 키, 국면, 경로, 속도, 힘, 그리퍼 상태, 정지, 게이트 결과, 실행 ACK)을 약 15 token으로 넣는다. 이 필드는 어떤 데이터에서도 라벨로 대체하지 않는다. 전문가가 수집한 에피소드에서는 전문가의 실행이 곧 이력이고, DAgger 에피소드에서는 모델 답을 하네스가 채택한 결과가 이력이다. 모델 raw 출력, 하네스 채택 결과, 실행 ACK, 전문가 라벨은 레코드에서 분리 필드로 둔다(8절). 실행 시 분포가 밀리는 문제는 7절의 DAgger식 재라벨링이 보정한다.

| prefix | 600~1,000 → **실측 382~385** | 지시·제약·질문 세트·정적 후보·표지 선언 |
| 틱당 새 토큰 | 450~700 → **실측 1,764~3,469(최초 틱, 물체 6·K12 → 10·K32), 후속 틱 최대 3,712** | 실측(2026-09-19, Qwen3.8-27B tokenizer, 서식 h0.3/ts0.3, `scripts/measure_tokens.py`): 숫자가 자리마다 1토큰, 물체 한 줄 ≈98, 후보 한 줄 ≈59. 추정은 성립하지 않으며 서식 축약·변화분 틱(계약 v0.3, 목표 ≈500/틱)이 전제 |
| 10초 학습 구간 | (03·05의 55K 가정) → **실측 서식 176K~371K, v0.3 목표 ≈50K** | 100틱 × 틱당 토큰 |

단일 H100(4×10¹⁴ FLOPs/s 가정)의 연산량 계산값은 틱당 550 token에서 27B dense 약 74ms, 9B 약 25ms다(450~700 token이면 27B 61~95ms, 9B 20~32ms). **배포 장비 실측(2026-09-19, DGX Spark GB10, native BF16, 03 §"지연 예산" 표)은 이 계산값이 성립하지 않음을 보였다**: 500토큰 틱·윈도우 크기 캐시에서 2B ≈83 ms, 4B ≈197 ms, 9B ≈278 ms(자라는 캐시의 p95는 123/305/378), 현재 서식(≈1.85K/틱)에서는 928/2,299/2,447 ms, 27B는 500토큰에서 886 ms. 이에 따라 G0b 후보는 2B(주)·4B(5 Hz 대비)이고 9B·27B는 10 Hz 트랙 밖이다(HANDOFF 결정 3). 3D 요약 필드를 넣은 상한(700)에서는 27B가 10Hz 예산을 넘으므로, 27B로 가려면 물체별 필드를 줄이거나 변화분 틱이 필요하다. 여기에 윈도우 attention(27B 기준 30틱×550 token의 KV 약 1.0GiB — 실측 재현 1.007 GiB; QK/AV 약 3.6TFLOP으로 같은 가정에서 약 9ms — **실측은 2B에서도 ≈32 ms**, sdpa가 마스크를 물질화한 채 sm80용 memory-efficient 커널로 실행되어 FLOP 시간의 ≈8×; 마스크 없는 윈도우 attention 커널이 G0b의 첫 지렛대), recurrent 연산의 실제 효율, 분기·cache 관리, 직렬화·전송·검증 시간과 지연 꼬리가 더해진다. 10Hz는 목표이며 판정은 실측한 모델 시간, 관측→명령 적용 시간, **100ms deadline 초과율**로 한다. 초과하면 변화분 틱 또는 작은 backbone으로 조정한다. 토큰 수도 실제 tokenizer로 물체 6/10개, K=12/32, 지시 변경, 긴 의미 설명의 분포를 측정한다(K=32에서는 후보 부분만 약 480 token).

## 4. 출력 계약: 질문 세트 v0

틱마다 아래 10개를 병렬로 묻는다. 질문 세트는 하네스 버전으로 고정하고, 후보는 틱마다 바뀐다. 결정 위치는 서로를 보지 못하는 일시적 분기이지만 공통 상태가 질문 세트를 조건으로 하므로 질문 간 격리는 보장하지 않는다(3.1절). 틱 사이의 연속성은 스트림이 제공한다.

| ID | 질문 | 타입 | 후보·기준 | 참조 대상 | 하네스 사용 |
| --- | --- | --- | --- | --- | --- |
| `q_main` | 지금 실행할 행동 | choice | 결합 후보 = 기능(grasp/place/push) × 대상 × 접근·접촉 × 목적지 × 프로파일, 각 후보에 `action_ref`·설명·파생 값. 여기에 observe·hold·replan. K≤32 | 현재 틱 | 목표·모드 결정 |
| `q_done` | 현재 목표를 이미 만족했는가 | boolean | 관측 가능한 목표 조건 | 현재 목표 버전 | 완료 절차 |
| `q_instr` | 실행에 필요한 지시가 충분한가 | boolean | 대상·목표·제약의 완결성(지시 텍스트 자체의 문제이며 대상의 현재 가시성과 무관) | 현재 목표 버전 | 재계획·질의 |
| `q_observe` | 관측을 더 얻어야 하는가 | boolean | 관측 나이·가림·필요 정보(지시의 대상이 아직 관측되지 않은 경우 포함). 파지·놓기 국면에서 팔이 대상을 가리는 것은 관측 부족이 아니다 | 현재 틱 | 관측 분기 |
| `q_retry` | 직전 실패와 같은 방식의 재시도가 적절한가 | boolean | 실패 이력 | 현재 틱 | 같은 방식 후보의 실행 조건 |
| `q_stop` | 지금 즉시 멈춰야 하는가 | boolean | 사람·충돌·낙하 위험, 잘못된 행동 진행 | 현재 틱 | 최우선 정지, 혼합 우회 |
| `q_gripper` | 원하는 그리퍼 상태 | choice | open / closed | **틱 시작 시 commitment와 국면** | 실행기가 상태 변화를 이벤트로 변환 |
| `q_path` | 경로 | choice | direct(대상) / via W1..Wn(n≤3, 하네스 국소 플래너) / retreat / hold | **틱 시작 시 commitment와 국면** | `command.path` |
| `q_speed` | 속도 수준 | ordinal | 0 / 0.1 / 0.25 / 0.5 m/s | **틱 시작 시 commitment와 국면** | 속도 상한 |
| `q_force` | 접촉·힘 수준 | ordinal | 회피 / 가벼운 접촉 / 밀기 | **틱 시작 시 commitment와 국면** | 임피던스·접촉 허용 |

**부가 질문의 참조 대상.** `q_gripper`·`q_path`·`q_speed`·`q_force`는 틱 시작 시 확정된 commitment(`action_ref`와 국면)에 대한 답이다. 질문 텍스트에 그 참조가 들어가고, 후보(경유점 등)도 그 행동 기준으로 만든다. `q_main`이 다른 행동을 고르고 하네스가 전환을 확정한 틱에는 이 네 답을 폐기하고 새 후보의 프로파일 초기값을 적용한다. 새 행동에 대한 부가 답은 다음 틱부터 나온다. commitment가 없는 틱(에피소드 시작, 해제 직후)에는 부가 질문을 마스킹하거나 hold 기준으로 묻는다.

**그리퍼와 정지.** 이벤트 대신 원하는 상태를 매 틱 내므로 답이 멱등이고, 실행기가 상태 변화 시점에 close/open 이벤트를 한 번만 발생시킨다(이벤트 ID·ACK·중복 방지). close는 commitment의 대상에 대한 접촉·도달 readiness, open은 놓기 국면의 release readiness를 실행기가 확인한 뒤 실행한다. `q_stop`은 허용 지연이 없고 반사와 같은 우선순위다.

확률의 의미는 다음과 같이 고정한다. choice 분포는 "적합 후보 집합에 대한 확률"이다. 집합 안의 상대 확률은 일반적으로 식별되지 않으며, commitment가 유일 정답을 만드는 틱에서만 정책 모방 라벨이 생긴다(7절). 전환 규칙의 `δ`는 dev 데이터에서 조정하는 경험적 여유이고, 후보 수·복제에 따라 같은 의미를 갖는다고 가정하지 않는다. 보정된 확률 주장은 타입·질문별로 정의한 사건과 평가에 한정한다. 사건의 물리적 성공 확률은 별도 Bernoulli 질문으로만 다루며 choice와 합치지 않는다.

## 5. 하네스 조합 규칙 v0

틱마다 아래 순서로 적용하고 충돌 건수를 기록한다.

0. **유효성 검사.** 응답의 `observed_at`이 관측 deadline(200ms) 안이고, `goal_version`·후보 집합 버전·요청 순번이 현재와 일치할 때만 아래로 진행한다. 선택된 후보가 참조하는 대상의 기하 나이가 **적용 시각 기준**으로(요청 시점의 나이에 모델·전송 경과 시간을 더해) 허용치를 넘으면 그 후보를 적용하지 않고 관측 분기로 보낸다. 말단이 이미 대상의 행동점에 들어온 파지·놓기·밀기(접촉) 국면과 대상을 들고 있는 동안에는 기하 나이 대신 실행기의 readiness(대상 거리·접촉·하중)가 시점을 정한다 — 밀리는 물체는 접촉 중에 기하가 계속 낡으므로 나이로 끊으면 밀기가 중간에 끊긴다(3c-2 실측). 아니면 응답을 폐기하고 사건으로 기록한다.
1. **반사·정지.** 실행기 반사 또는 `q_stop`이 참이면 즉시 정지 전이(혼합 우회). 다른 답은 이 틱에 적용하지 않는다. commitment는 유지한 채 다음 틱에 재판단하고, 정지가 `m=2` 틱 이상 이어지면 해제한다.
2. **게이팅.** `q_done`이 참이면 완료 절차. `q_instr`이 거짓이면 재계획·질의. `q_observe`가 참이면 관측(운반 중이면 `hold` 후 관측). 관측은 제자리 정지가 아니라 **설정된 관측 자세로 이동한 뒤** 새 관측을 기다리는 동작이다 — 팔 자신이 가림의 원인이면 제자리에서는 풀리지 않는다. 게이팅이 발동하면 commitment를 해제한다.
3. **주 결정과 결정 유지.** `q_main`의 선택 후보에 히스테리시스를 적용한다. 의미 키는 `기능·대상·접근 유형·목적지·프로파일`이며 연속 파라미터는 허용 오차로 비교한다. 현재 후보가 목록에 남아 있으면 유지하고, **같은 도전자**가 `δ=0.15` 이상 높은 상태로 `m=2` 틱 연속일 때만 전환한다. 도전자가 바뀌면 카운터를 초기화한다. 목표 버전 변경, 행동 완료, 현재 후보 무효화 시에는 commitment를 해제한다. 전환·해제·유지는 `action_ref`와 함께 기록한다.
4. **부가 답의 적용.** commitment가 유지된 틱에는 `q_path`·`q_speed`·`q_force`·`q_gripper`를 그 commitment의 프로파일·제약 안에서 적용한다(취약 물체 인접 시 힘 수준 상한 등). 전환 틱에는 네 답을 폐기하고 새 후보의 초기 프로파일(경로는 **막히지 않은 경로** — direct가 관측된 장애물에 막히면 국소 플래너의 첫 경유 경로, 그것도 없으면 hold와 충돌 기록; 속도 1단계, 힘 회피, 그리퍼 현재 상태)을 적용한다.
5. **그리퍼 이벤트.** `q_gripper`가 현재 상태와 다르면 실행기가 readiness를 확인한 뒤 이벤트를 한 번 발생시키고 ACK를 돌려준다. readiness 미충족은 기록하고 대기한다.
6. **명령 생성.** 6절 형식으로 조합하고 순번·`observed_at`·`goal_version`·`action_ref`·국면·lease·대상 기하의 관측 시각을 부착한다. 국면별 목표점은 approach → 접근점, grasp → 파지점, lift → 현재 XY에서 들기 높이까지 수직 상승, transport → 목적지 위 접근점(들기 높이 유지), place → 목적지 놓기점으로 하강, push → 접촉점에서 밀기 구간이다. 하네스는 **실제로 명령할 구간**(말단→목표점, via면 말단→경유점)을 관측된 장애물에 대조한다. 막힌 direct는 보내지 않고 경유 경로나 hold로 바꾸며 충돌을 기록한다. 금지 접촉 물체는 플래너가 여유를 더 둔 장애물로 취급해 경유 경로가 있으면 우회하고(`forbidden_reroute` 기록), 경로가 없을 때만 hold에 `forbidden_segment`를 붙여 실행기가 정지 전이하게 한다. 그 상태가 `m` 틱 이어지면 `forbidden_blocked`를 기록하고 commitment를 해제한다. 답한 경로와 다르게 실행된 경로(우회·hold)는 채택 결과와 실행 이력에 **실제 경로**로 적는다. 국소 충돌 검사·도달 검사·전환 구간 검사에 걸리면 거절 사유를 사건으로 올린다.

규칙 기반 판단기 기준군은 같은 입력(구조화된 목표·제약 포함)에서 같은 10개 답을 규칙으로 내고, 같은 조합 규칙을 거친다.

## 6. 컨트롤러 계약

```text
command = {
  seq, request_id, observed_at, issued_at,
  lease_until (= issued_at + 300ms), goal_version, candidate_set_version,
  action_ref, phase,
  path:  direct(target_ref) | via(waypoint_ref) | retreat | hold,
  speed_level → 속도 상한 (0 / 0.1 / 0.25 / 0.5 m/s, 하네스 정의),
  force_level → 접촉 허용·임피던스 (회피 / 가벼운 접촉 / 밀기),
  gripper: open | closed (원하는 상태),
  stop: bool,
  gripper_ref, frame, constraints(금지 영역, 속도 한계, forbidden_segment),
  geometry_observed_at (명령이 참조하는 대상 기하의 관측 시각), target_moving
}
```

| 항목 | 동작 |
| --- | --- |
| 수명 | 세 가지를 따로 검사한다. **관측 deadline:** 로봇 고유 감각 기준 `observed_at`에서 200ms가 지난 명령은 적용하지 않는다. **기하 나이 허용:** 명령이 참조하는 대상의 3D 재구성 나이를 **적용 시각에** `geometry_observed_at`으로부터 계산해, 허용치(정지 물체 500ms, 외란·이동 대상 200ms, 시작값)를 넘으면 그 명령을 적용하지 않고 관측을 요청한다. 파지·놓기·밀기(접촉) 국면과 파지 중에는 이 검사 대신 readiness가 시점을 정한다(5절 0항). **발행 lease:** `lease_until`까지 이전 명령을 계속 실행한다. 순번이 역행한 명령은 폐기 |
| 혼합 | 새 명령 도착 시 목표 속도를 100ms 동안 보간해 전이한다. 전환 구간의 궤적을 국소 충돌 검사하고, 걸리면 정지 전이로 바꾼다 |
| stale | lease가 끝나면 감속 정지하고 그리퍼 상태를 유지한다. 1초 이상 지속되면 `HOLD` 절차 |
| 정지 전이 | `stop` 또는 반사 시 혼합을 우회해 정해진 감속 프로파일로 정지한다. 파지 중이면 유지 |
| 반사 | 힘 한계 초과 → 즉시 정지, 근접 위험 → 감속, 미끄러짐 → 파지 유지와 사건 보고. 모델 응답을 기다리지 않는다 |
| 그리퍼 | `gripper`가 현재 상태와 다르면 readiness 확인 후 이벤트를 한 번 발생시키고 이벤트 ID로 ACK. 중복 적용 없음 |
| 거절 | 경로가 국소 충돌 검사나 도달 검사에 걸리면 실행하지 않고 사유를 사건으로 올린다 |
| 관측 | `observe` 명령은 설정된 관측 자세로 이동한 뒤 정지하고 새 관측을 기다린다. 실행 기록은 실제 이동을 말한다 |
| 요청 정책 | 하네스는 모델이 준비될 때 최신 관측으로 다음 틱을 만든다. 큐를 쌓지 않으며 지연된 요청은 폐기하고 기록한다. 틱 주기는 `max(100ms, 모델 시간)`이고 10Hz는 목표다 |
| 주기 | OSC 말단 목표 갱신 50Hz, 보간은 그 주기에서. OSC의 토크 계산과 물리는 500Hz |

300ms lease는 0.5m/s에서 명목상 15cm 이동에 해당하며 감속 거리는 별도다. lease·deadline·혼합 시간은 속도·여유 거리·정지 동작과 함께 검증하는 실험 시작값이다. 이 계약은 모델, 규칙 기준군, 분해형 비교 구성에 동일하게 적용하고 버전을 기록한다. 학습형 컨트롤러로 바꿔도 명령 형식과 수명·정지·반사 규칙은 유지한다.

## 7. 라벨 계약

| 질문 | 라벨 원천 | 형태 |
| --- | --- | --- |
| `q_main` | (1) 의미 적합성 규칙: 지시·목적지·금지 조건으로 `semantic_admissible` 산출. (2) 적합 후보 안에서 실행 성과 비교: rollout이 있는 키프레임 틱은 같은 목표·horizon·후속 정책 아래 후보별 성공률과 불확실성(censoring 반영, paired seed), 나머지 틱은 플래너 비용. (3) commitment 규칙: 현재 실행 중인 후보가 적합하고 최고 후보와의 성공률 차이가 허용 여유 `ε=0.15` 이내이며 성공률 하한이 기준(0.5) 이상이면 그 후보만 정답. 근거가 약하면(구간이 넓거나 rollout 집합에 없음) 유일 정답 대신 복수 허용·추가 rollout·낮은 라벨 신뢰도 중 하나 | 허용 집합 + 미확인 집합. `semantic_admissible`, `event_results`(seed별 보존), `unknown`, `choice_label`, `label_confidence`, 규칙 버전을 별도 필드로 보존 |
| `q_done`·`q_instr`·`q_observe`·`q_retry` | 목표 평가기, 지시 완결성 규칙, 관측 나이·가림 규칙, 실패 이력 규칙 | boolean |
| `q_stop` | 전문가 정지 조건과 반사 조건. 허용 지연 없음 | boolean |
| `q_gripper` | 전문가가 그 틱에 원하는 그리퍼 상태. 전환 틱 ±1틱은 두 상태 허용, 그 외는 단일 정답 | choice 허용 집합 |
| `q_path` | commitment 기준으로 전문가가 택한 경로. 충돌 없고 비용이 비슷한 대안 경유점은 허용 집합에 포함 | choice 허용 집합 |
| `q_speed` | commitment 기준 전문가 속도 프로파일을 4수준으로 양자화. 취약 물체·외란 근접 시 규칙으로 하향. 경계는 인접 수준 허용 | ordinal 허용 집합 |
| `q_force` | commitment 기준 전문가의 **목표 접촉 모드**(임피던스·허용 접촉 설정). 관측 접촉력은 라벨이 아니라 상태 | ordinal |

- 관측·보류·재계획 후보는 규칙 라벨로만 정답이 되며 사건 성공률과 비교하지 않는다. 근거가 없는 질문은 loss mask.
- 적합성 규칙은 추론 시 후보 생성기에 넣지 않는다. 하네스는 적합하지 않은 실행 가능 후보도 그대로 제시한다.
- **미확인 후보.** 키프레임에서 rollout하지 않은 후보는 `unknown`으로 두고 부분 라벨 손실 `-log(Σ_A p_k / (Σ_A p_k + Σ_I p_k))`로 학습한다. `A`는 허용, `I`는 부적합·열등 판정 후보이며 `unknown`은 정규화에서 빠진다. 현재 commitment와 전문가 선택은 항상 rollout 집합에 포함한다.
- 성공률 비교는 횟수 차이가 아니라 성공률과 신뢰구간으로 한다. censoring으로 유효 반복 수가 다르면 그 수로 계산하되, censoring이 선택적일 수 있으므로 사유를 보존하고 편향을 별도 검토한다. seed 8회는 초기 선별용이며 근소한 차이를 판정하는 표본 수로 취급하지 않는다.
- **부가 질문 라벨의 조건.** `q_gripper`·`q_path`·`q_speed`·`q_force`의 라벨은 그 틱의 실제 commitment(`action_ref`·국면)에 조건화한 전문가 답이다. 전문가 에피소드에서는 전문가의 commitment, DAgger 에피소드에서는 모델이 채택한 commitment가 조건이다. 조건이 되는 commitment가 부적합하면 부가 답은 "안전한 기본값"(hold·저속·회피·현재 그리퍼 상태)으로 라벨하거나 마스킹한다.
- **DAgger식 재라벨링.** 학습 버전이 나올 때마다 robojev를 시뮬레이션에서 200 에피소드 실행한다. 레코드에는 모델 raw 출력, 하네스 채택 결과, 실행 ACK를 **그대로 보존**하고, 그 상태에서 전문가가 지금 고를 답을 labels에만 기록한다. 입력의 실행 이력·commitment는 바꾸지 않는다. 새 에피소드에 정책 오류·복구 상황·commitment 변경이 얼마나 포함됐는지 집계한다. 혼합 비율 70/20/10은 기존 자료·오류 계열·새 의미 계열의 축이고, 로봇/비로봇 비중은 별도 sampler 축이다.
- **Rollout 예산(시작값).** 에피소드당 키프레임 5틱(이벤트·전술 변경 시점 + 무작위, 사건 종류별 포함률 기록) × 400 에피소드 = 2,000 상태 × 결합 후보 8 × seed 8 = 128,000 rollout. 5초 구간이면 약 178 모의 시간. reset·snapshot 복원·후속 정책 비용은 첫 100개 실측으로 재산정.

데이터의 독립 단위는 **에피소드**다. 틱은 상관되어 있으므로 독립 표본으로 세지 않는다. 에피소드 수, 틱 수, 질문 수를 각각 집계한다.

예시는 한 틱의 축약이며 실제 레코드는 에피소드 시작부터의 모든 틱을 가진다. `model_output`, `adopted`, `ack`, `labels`는 항상 분리해 저장한다. 전문가 에피소드에서도 네 필드를 모두 채운다: `model_output`은 그 에피소드를 실행한 정책(전문가)의 raw 답, `adopted`는 하네스가 조합 규칙으로 채택한 결과, `ack`는 실행 ACK, `labels`는 전문가 라벨(`source: expert_v0`)이다. 그래야 D1(전문가 실행)과 DAgger(모델 실행 + 전문가 재라벨)가 같은 형식이 된다. **버전·지문(구현이 정한 세부, 2026-09-19).** 레코드의 `versions`에는 하네스·컨트롤러·전문가·추출기·규칙 기준군·레코드 직렬화·장면 설정 버전과 `config_digest`(하네스·컨트롤러·전문가·장면·사건·규칙 기준군 설정과 생성기의 `episode.*` 항목을 정렬한 JSON의 sha256)가 들어가고, rollout 재생은 이 키들이 실행 중인 것과 다르면 `ConfigMismatch`로 거부한다(조용히 건너뛰지 않는다). 토큰 직렬화(모델 입력 서식)는 별도 버전 `ts0.x`이며 학습 manifest에 기록한다. DAgger 사이클의 에피소드는 seed를 `base + (cycle+1)·offset`부터 세고 id에 `-dagger{cycle}`을 붙여 전문가 배치와 충돌하지 않게 하며, origin group·split은 장면 계열을 따른다. `label_confidence: low`인 라벨은 설정의 `weight`(시작값 0.25)로 낮춰 학습하고 step 지표가 그 수를 따로 센다; 답 집합이 빈 라벨은 쓰지 않는다(mask).

**D1 목표 규모(시작값).** 로봇 400 에피소드(약 30초, 약 120K 틱, 약 1.08M 질문) + 비로봇 단일 요청 2,000 상태(약 16K 질문) + 기존 OOD 세트. 합계 약 1.1M 질문은 기존 D1(약 4만)의 약 27배이지만 틱은 독립 표본이 아니다. 분야 비중은 상태 수가 아니라 학습 토큰과 sampler 가중치로 관리하고, 실제 유효 loss 비중(질문별 평균과 시퀀스 토큰 비중은 다르다)을 함께 기록한다. 정상 유지 틱의 중복과 이벤트·목표 변경 틱의 희소성은 별도로 가중한다.

**학습 시퀀스.** 에피소드를 순서대로 10초 구간(약 100틱, prefix 별도 약 55K token)으로 나누고, **같은 optimizer step 안에서** 구간을 차례로 forward·backward하며 DeltaNet·conv 상태와 윈도우 KV를 detach해 다음 구간에 전달한다(truncated BPTT). 한 에피소드가 하나의 gradient accumulation 단위다. 이렇게 하면 추론과 같은 가중치·같은 이력의 상태를 얻으므로 warm-up이 필요 없고 모든 틱에 loss를 준다. 구간 경계에서 gradient는 끊긴다. 구간당 활성 메모리(약 55K token)는 27B보다 9B 후보에 유리하므로 Task 2b의 선정 기준에 넣는다.

분할은 장면 계열 단위로 생성 전에 배정하고, 같은 에피소드의 틱·rollout·crop·재라벨링 파생본은 모두 그 split을 상속한다.

## 9. 제작 파이프라인

```text
장면 계열 설계와 split 배정(train/dev/calibration/test/OOD)
  → 장면 생성(물체 6~10개, 취약·금지 속성, 영역)
  → 지시 스크립트(시작 지시 + 5~15초 사이의 지시 변경)
  → 외란 일정(wrapper가 무작위 시점에 물체 이동, 모의 시간·seed로 정의)
  → 스크립트 전문가가 10Hz로 명령 생성하며 에피소드 실행
  → 하네스가 틱마다 요청(상태·후보·실제 실행 이력)과 채택·ACK를 기록
  → 규칙·전문가·키프레임 rollout으로 라벨(입력은 바꾸지 않음)
  → 자동 QA(입력/라벨 분리, 정보 경계, 참조·확률·순서, 계보) + 표본 검수
  → manifest 동결 → 학습 → 200 에피소드 실행·재라벨(split 상속) → 다음 버전
```

전문가는 접근·파지·들기·이동·놓기·밀기 국면과 국소 충돌 검사 기반 경유점을 가진 스크립트 정책이다. 가림·차단 시 규칙으로 관측·보류를 택한다. 전문가의 행동 다양성 한계는 D2에서 최적화·RL 전문가와 비교한다.

## 10. 평가 연결

- 질문별 오프라인 지표(정확도·허용 집합 적중·NLL·Brier·ordinal 오차)를 스트림 조건에서 계산한다. 관측 잡음 변형에서의 뒤집힘 비율을 포함한다.
- 그리퍼·정지: 이벤트 누락률, 중복률, 발생 시각 오차, `q_stop`의 지연과 오경보율.
- 폐루프: 성공률(규칙 기준군 대비, 기하 충분 층·의미 판단 층 분리), 완료 시간, 외란·지시 변경 후 반응 지연, 결정 전환율·왕복 전환·유지 시간, 목표 변경 후 반응 지연과 완료된 행동의 반복 실행 여부.
- 지연: 연속 틱 조건의 틱당 모델 시간과 관측→명령 적용 시간의 p50/p95/p99, 100ms deadline 초과율, 관측 deadline 폐기율, lease 만료율, 컨트롤러 거절률, 혼합·정지 전이의 속도 불연속과 전환 구간 충돌 검사 결과.
- 격리·정합성: L1-a에서 질문 하나를 바꿨을 때 다른 답과 다음 틱 상태의 변화(품질 지표), 증분 계산과 처음부터 계산의 일치(윈도우 절단 제외), 가려진 참값 변경 시 입력 불변.
- 대조 검사: 성공률이 같고 지시만 바뀐 쌍에서 `q_main` 정답이 바뀌는지, commitment가 있는 쌍에서 유지가 학습되는지, 전환 틱에서 부가 답이 폐기되는지.
- 선택적 지표: 게이트(observe·hold·replan)를 abstention으로 보고 coverage(행동한 비율)·abstention 비율·selective accuracy(행동한 틱의 정확도)·wrong target·**unsafe action rate**(금지 접촉·정지 무시 등 안전 규칙 위반 행동의 비율)를 따로 낸다. 문맥 섞기 대조군(03 §6)도 스트림 조건에서 계산한다.

## 12. 후속·미결

- 영상 입력(`image[]` 슬롯)과 학습형 기하 인코더(`geom[]` 슬롯), 절대 방향 bin ablation. 두 슬롯 모두 어댑터·backbone 재학습이 따르는 확장이다.
- 3D 재구성 파이프라인의 실측 갱신 주기·지연·정밀도로 소스별 deadline과 스키마 필드를 확정.
- 학습형 RL 컨트롤러로의 교체와 전이 최적화.
- 사람 손 데이터에 근거한 정교한 접촉 조작.
- 후속 작업: 사람과의 핸드오버·양보, 양팔 분담.
- 변화분 틱과 backbone 규모(27B/9B)는 Task 2b 실측으로 결정. 9B부터 실제 스트리밍 경로(결정 분기·상태 전달·윈도우)를 계측하고 27B는 같은 조건의 비교 후보로 유지.
- 격리를 유지하는 L1-b(상태가 질문을 보지 않고 결정 위치만 자기 질문과 상태를 참조)는 full-attention 후보에서만 성립하므로 별도 실험.
